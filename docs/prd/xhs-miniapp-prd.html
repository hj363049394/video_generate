小程序版 PRD：把「编辑部」装进微信

小红书仿写助手 · 微信小程序形态 —— 面向自媒体小白与代运营客户的合规主入口

版本 v1.0（评审稿） 日期 2026-10-08 上游文档 设计文档 v1.1 · v1.4.0 变更（重方案 / 效果回流 / 成本账本） 状态 待评审 [TBD：产品名与小程序类目]
v1.4.0 已在微信 Bot 上跑通完整闭环：定位 → 每日专属选题 → 确认生产 → 成品交付 → 发布登记 → 每日数据回采。但 Bot 作为商业化载体存在三大约束（推送配额、会话保活、风控），且指令交互对自媒体小白门槛过高。本 PRD 定义微信小程序版：以可视化界面承载既有生产能力，以订阅消息解决合规触达，让「不会用指令的人」也能完成从选题到效果复盘的全流程。

§1背景与痛点

1.1 已确认的事实基础

  • 已落地 生产线：红狐抓取 → 数值+语义四维评分 → 仿写 → 图文卡片 → 视频按需生成；多用户重方案（每人按自己的关键词/人设独立评分、独立推送清单）已上线。
  • 已落地 效果回流：/已发布 登记发布链接，每日定时回采赞藏评并推送增量日报；成本账本可查单篇花销。
  • 已验证 微信 Bot（ClawBot iLink）单号可服务多用户，但存在 §1.2 三大约束；飞书替代方案已被应用商店驳回（非企业办公类应用）。
  • 已确认 目标用户：自媒体小白（大学生、小红书新手主理人，旅行赛道为主）；近期将接入代运营客户——效果数据展示是其付费核心理由。

1.2 痛点清单

编号痛点描述直接影响
P1风控不可承诺Bot 账号一旦封号，该号下所有付费用户同时失联，SLA 无法承诺。不敢收费，商业化被卡死
P2推送配额挤占每用户 24h 主动推送约 10 条；一单成品交付拆 6–9 条消息已贴近上限，选题清单、数据日报还要再挤。关键通知被丢弃或降级
P3会话保活依赖会话令牌需用户每天说话续期，沉默用户收不到任何推送——数据日报对沉默用户失效。效果回流卖点断链
P4指令门槛/定位 /选题 /确认 N /换角度 N /已发布 /效果 /成本 共 10+ 条指令；小白记不住、不敢用。激活与留存受损
P5消息流不可视选题评分、赞藏评趋势、成品图文全部以纯文本呈现；数据无法沉淀为可回看的看板。付费价值感知弱

§2解决方案与产品形态

2.1 形态决策

决策：以微信小程序为主入口，订阅消息为合规触达通道，网页管理后台（另立项）服务主理人，Bot 降级为可选辅助渠道。

端定位解决的痛点
微信小程序创作者主入口：定位、选题、生产、交付、效果查看全流程可视化。P1 合规载体（官方容器无封号失联风险）、P4 零指令门槛、P5 可视化
订阅消息关键节点触达：选题日报、任务完成、数据日报（详见 FR-07）。P2 按需触达不占 Bot 配额、P3 无会话保活依赖
网页后台主理人/代运营视角：多客户账号管理、成本对账、效果汇总报表。多账号批量管理不适合手机端（另立项，不在本 PRD 范围）
微信 Bot降级为可选渠道：老用户过渡期保留，不再新增能力。—

2.2 为什么不是 App / 纯 H5

  • App：下载安装对小白用户是第一道流失口；微信生态内传播（朋友圈/群/小程序卡片）无法直达。
  • 纯 H5：微信内无法申请订阅消息授权，触达问题（P2/P3）无解；会话保活问题依旧。

§3范围

3.1 P0 最小完整旅程

入口条件：微信用户首次打开小程序。
旅程：微信一键登录 → 三步定位引导 → 看到今日专属选题清单 → 选一条「照这个写」→ 观看生产进度 → 收到成品（图文预览+发布文案）→ 发布后登记链接 → 次日看到该笔记的赞藏评数据。
完成证据：用户在「数据」页看到自己已发布笔记的真实回采数据与增量。
关键恢复路径：生产失败的任务可一键重试（见 FR-04 异常）。

3.2 优先级边界

批次内容
P0FR-01 登录与账号 · FR-02 定位引导 · FR-03 今日选题 · FR-04 生产任务 · FR-05 成品交付 · FR-06 发布登记与效果看板 · FR-07 订阅消息触达
P1FR-08 成本明细页 · FR-09 直发仿写（粘贴链接/长文本）· 历史清单日期切换 · 主题探索（对应 Bot /主题）
P2主理人多客户视图 · 网页管理后台 · 视频成品展示（生产端已支持，小程序端展示后置）

明确不做：小程序内不做账号矩阵管理、不做评论代回复、不做粉丝画像分析——均属网页后台/远期范围。

§4产品模型

4.1 对象与关系

对象定义与 Bot 版对应
用户微信 openid 唯一标识；与 Bot uid 同一体系映射，两端口径互通。uid
定位赛道 + 人设 + 关键词（数组），每用户一份；驱动评分与仿写。user_profiles（/定位）
选题雷达产出的单条候选：标题/热度/四维评分/仿写角度/人设钩子；按用户专属清单组织，每日一份。topic_list_{date}.json（重方案个人目录）
任务一次生产：选题 → 拆解 → 仿写 → 配图 → 交付；有唯一任务号与状态机。tasks
发布记录任务交付后用户登记的小红书链接 + 回采的指标快照序列。published_url / metrics

4.2 任务状态机（跨端共享，Bot 与小程序一致）

queued 已排队→ rewriting 拆解仿写→ imaging 配图→ delivered 已交付
failed 失败← 任一环节可失败，可重试；重试回 queued

已交付任务追加登记发布链接后进入「已发布」标记态；发布记录的回采不改变任务状态。

4.3 用户旅程图

阶段用户动作系统响应触达
① 进入打开小程序，微信一键登录无定位 → 进引导；有定位 → 进今日选题—
② 定位三步填写赛道/人设/关键词保存定位；生成首份专属选题清单（异步）任务完成通知
③ 选题浏览清单，点「照这个写」任务入队，进度页实时刷新生产完成通知
④ 交付预览图文、复制发布文案、存图引导「发布后回来登记」—
⑤ 登记粘贴发布链接关联最近已交付任务，纳入每日回采—
⑥ 复盘打开数据页看赞藏评与增量每日自动回采；日报推送数据日报

§5功能需求

FR-01登录与账号P0
触发
用户首次打开小程序，或本地凭据失效时。
处理
微信一键登录（不弹授权弹窗收集昵称头像）。openid 映射到内部 uid；若该 uid 已有 Bot 使用记录，自动继承其定位、任务、发布记录与成本数据。
结果
登录态静默保持；进入首页时按「有无定位」分流到 FR-02 或 FR-03。
边界
登录失败：展示重试入口，不阻塞浏览空态首页。老用户继承逻辑失败时按新用户处理并提示可联系主理人找回。
FR-02定位引导（Onboarding）P0
触发
登录后无定位记录，用户点击「设置我的定位」。
布局
三步向导，每步一屏：① 选赛道（预设旅行方向单选+自定义输入）→ ② 写人设（一句话自我介绍，示例引导文案）→ ③ 填关键词（1–5 个，逗号分隔，chip 呈现可删）。
规则
与 Bot 口径一致：至少填「人设」或「关键词」一项才能提交；关键词空格/逗号/顿号混输均容忍。提交即保存并触发首份专属清单生成（异步，见 FR-03 抓取态）。
结果
保存定位 → 跳转首页，首页展示「清单生成中」的抓取态；完成后清单卡片流入场。
异常
抓取失败（无候选/服务异常）：首页显示失败原因与「重试抓取」按钮，不回退定位数据。
FR-03今日选题清单（首页）P0
触发
每日进入首页；或用户下拉刷新 / 点击「重新抓取」。
布局
顶部刊头（日期 + 「今日 X 条选题，按你的定位评分」）→ 选题卡片流，默认展示前 5 条，展开加载全部 → 每卡：标题、热度标签（赞藏计数）、四维评分条（相关/爆点/人设契合/转化）、仿写角度一句话、人设钩子、主按钮「照这个写」。
规则
① 默认读用户专属清单（重方案：按该用户关键词+人设独立评分）；无专属清单时回退全局清单并明确标注「通用清单 · 设置定位后更准」。
② 每日雷达由系统定时跑（Bot 与小程序共用一次抓取，不重复消耗）；「重新抓取」走按需抓取，相同日期内覆盖个人清单。
③ 卡片展示与 Bot /选题 同源同序；评分低于语义硬门槛的淘汰项不在小程序展示。
④ P1 历史日期切换（近 7 天）与「按主题探索」（放开门槛为 0/0 的探索模式，结果标注「探索模式 · 门槛放开」）。
空态
当日无清单：区分「还没生成（去抓取）」「门槛筛后为空（展示漏斗数据：抓取 N → 达标 0，建议放宽关键词）」「抓取失败（重试）」三种，各配专属文案。
FR-04生产任务P0
触发
选题卡点「照这个写」；或历史任务详情点「重试」。
规则
① 确认即建任务入队（同 Bot /确认 N），同一选题可多次生成，任务号区分。
② 进度页展示四阶段步进条：拆解仿写 → 配图 → 交付（文案 + 图文卡片），每阶段完成即点亮；预估时长以「约 1–3 分钟」量级文案呈现，[TBD：实测后校准]。
③ 「换角度」入口：任务页改写仿写角度后重新生产（同 Bot /换角度 N）。
④ 用户离开小程序后生产继续；完成靠订阅消息（FR-07）召回。
状态与异常
失败任务在「生产」Tab 常驻展示失败原因（文案生成失败/生图通道失败），提供「重试」与「换生图通道」两个动作；重试生成新任务，原任务保留可追溯。
FR-05成品交付P0
触发
任务状态变更为已交付；用户从通知或「生产」Tab 进入。
布局
图文卡片轮播（首图突出，支持单张保存/批量保存到相册）→ 发布文案区（标题+正文+话题标签）→「一键复制全文」→ 交付清单摘要（张数/通道/生成时间）。
规则
① 文案复制保留小红书排版换行；复制成功有明确反馈并引导「发布后回来登记链接，开启数据追踪」。
② 交付消息拆条问题不复存在——小程序内一次呈现全部成品，不占用任何推送配额；推送侧只在完成时发 1 条通知。
③ 视频成品 P2：生产端已支持按需补生成，小程序端先行只读展示入口与跳转说明。
异常
图片保存到相册需相册权限：拒绝后提供「去设置开启」引导；图片链接过期时支持「重新取图」。
FR-06发布登记与效果看板P0
触发
交付后引导页；或「数据」Tab 点「登记已发布」。
规则
① 粘贴小红书链接（xiaohongshu.com/xhslink.com），校验合法性后关联该用户最近一条未登记的已交付任务；关联关系登记后可解绑重绑（解除前需确认）。
② 每日系统定时回采近 30 天内发布笔记的赞藏评（回采窗口与 Bot 共用配置口径）；数据页展示：赞/藏/评三卡（总量 + 今日增量）与近 30 天趋势。
③ 手动「立即刷新」单条笔记（每次刷新计一次详情抓取消耗，成本记入该用户账本）。
④ 增量日报由订阅消息推送（FR-07），数据页为完整看板。
空态/异常
无已发布笔记：空态引导回交付页。单条回采失败不影响其余条目；失败项标注「上次成功数据 + 失败时间」。
FR-07订阅消息触达P0
模板
① 选题日报：「今日 N 条选题已就绪，前 3 条标题摘要」→ 点击进首页。
② 任务完成：「你的笔记已生成（任务号）」→ 点击进交付页。
③ 数据日报：「昨日你的笔记 +X 赞 +Y 藏」→ 点击进数据页。
规则
① 订阅消息为一次性授权模型：每次用户授权可推送一条。授权收集节点固定在价值交换时刻——提交定位后（换任务完成通知）、复制文案后（换数据日报）、点开数据页后（换次日选题日报），绝不弹窗轰炸；单日单用户最多请求 1 次授权。
② 无授权或推送失败：内容降级为站内待读（首页红点 + 角标计数），下次打开必达。
③ 推送内容包含核心信息量（标题/增量数字），即使不点开也有价值。
④ [TBD] 模板类目可用性与字段上限以微信审核为准，文案模板预留可替换。
与 Bot 的关系
小程序用户默认不再走 Bot 推送；未迁移老用户维持 Bot 通道直至引导迁移完成。
FR-08成本明细页P1
触发
「我的」Tab → 成本明细；或任务详情 →「本篇花了多少」。
规则
① 单篇视图：该任务各环节用量与折算金额（提示词字符、生图张数、详情抓取次数）；汇总视图：近 7 天用量与金额。
② 金额为按配置单价的估算值，页面固定文案「按当前单价估算，以账单为准」；未配置单价时仅展示用量。
③ 付费用户成本透明是信任卖点；免费用户仅展示用量不展示金额。
FR-09直发仿写P1
触发
首页「+ 自由仿写」：粘贴小红书笔记链接，或直接输入首行标题+正文。
规则
与 Bot 拉模式同源：链接 → 抓详情（视频笔记提取口播文案）→ 按用户定位仿写；纯文本 → 直接生产。探索与仿写共用 FR-04 任务流。
异常
链接无效/抓取失败给出明确原因；视频提文案超时降级为仅看图拆解并标注。

§6界面设计

6.1 设计调性：「旅行编辑部」

用户是旅行自媒体人，产品要给的感受是——「有一位专业编辑每天为我的账号挑选题、写稿、盯数据」，而不是一个冷冰冰的 SaaS 工具。因此整体采用杂志编辑部风格：暖纸底色、衬线刊头、车票式标签、纸质卡片；克制、专业、有人味。拒绝科技感渐变紫与后台仪表盘味。本 PRD 的排版即此调性的示范。

卡片纸片隐喻：米白卡面 + 1px 纸边描边 + 微投影（2px 偏移硬影，非模糊大阴影），圆角 12px。
标签行李签/车票式胶囊标签（赛道、探索模式、热度）；评分用四维水平条，墨绿达标、沙金预警。
动效轻盈、有"翻页"感：清单卡片 stagger 入场（50ms 间隔）、按钮按压微缩 0.97、生产进度步进点亮带弹性；不做常驻循环动画。
空态插画 + 一句编辑口吻文案（如"今天编辑部还没挑出好题——换个关键词试试"），并永远给出下一步动作按钮。

6.2 信息架构

底部四 Tab：选题（首页）/ 生产 / 数据 / 我的。核心旅程「选题 → 生产 → 数据」各占一 Tab，符合每日使用节奏：早看选题、午管生产、晚看数据。

§7共享规则

7.1 通知策略（跨模块统一）

事件通道与时机降级
选题就绪订阅消息，每日雷达完成后（默认 8:00 档）首页红点待读
任务完成 / 失败订阅消息，状态变更即时生产 Tab 常驻 + 待读
数据日报订阅消息，每日回采后（默认 9:00 档）；仅当日有增量才推数据页查看
授权请求仅价值交换节点弹出，单日单用户 ≤1 次静默跳过

7.2 数据口径（与 Bot 版一致，一处定义）

  • 清单归属：有定位用户读个人专属清单（按其关键词+人设独立评分）；无定位用户读全局清单。个人清单按日覆盖。
  • 回采窗口：仅自动回采近 30 天发布的笔记；超窗笔记保留历史数据，可手动刷新。
  • 成本归属：生产记任务号、雷达记日期、回采记回采批次；单篇成本 = 该任务号全部条目聚合。
  • 同端互斥：同一 uid 同时只用一个活跃通道推送，避免双端重复打扰。

7.3 权限

操作规则
查看/生产/登记仅本人数据；uid 边界硬隔离（清单、任务、发布记录、成本均按 uid 过滤）。
定位修改本人可改，改后次日清单生效，当日的可手动重抓。
发布记录解绑需二次确认；解绑后该笔记停止回采。
