§1背景与痛点

1.1 已确认的事实基础

  • 已落地 生产线：红狐抓取 → 数值+语义四维评分 → 仿写 → 图文卡片 → 视频按需生成；多用户重方案（每人按自己的关键词/人设独立评分、独立推送清单）已上线。
  • 已落地 效果回流：/已发布 登记发布链接，每日定时回采赞藏评并推送增量日报；成本账本可查单篇花销。
  • 已验证 微信 Bot（ClawBot iLink）单号可服务多用户，但存在 §1.2 三大约束；飞书替代方案已被应用商店驳回（非企业办公类应用）。
  • 已确认 目标用户（v1.2 分层重构，R18）：核心付费用户 = 腰部个人博主（粉丝 1千–5万，周更 1–3 篇，¥49 档）与高频创作者（日更/准日更，¥99 档）；代运营主理人为高价值延伸（¥199+ 档，效果数据展示是付费核心理由）；素人新手为漏斗层（免费+¥0.99 体验卡）；企业级明确不做。赛道全面开放——关键词订阅机制按用户自定义赛道运作，不设类目限制。

§2解决方案与产品形态

2.1 形态决策（v1.2 改判，R19）

决策：以响应式 Web 应用（移动 H5 + 桌面增强，同一 URL 同一代码库）为主入口；认证服务号承担「入口 + 触达 + 登录」三合一基建；官网收款页为收款主通道；小程序降为 P2 观察项。

端定位解决的痛点
响应式 Web（主）创作者主入口：移动端覆盖「刷到→拆解→取走产物」轻交互（复制文案/长按存图/提交链接），桌面端承载长文案编辑、数据看板、视频上传等重交互。P4 零指令门槛、P5 可视化、桌面专业体验、免发版审核
认证服务号三合一基建：① 入口（菜单/模板消息→H5）② 触达（模板消息，沉默用户覆盖优于小程序订阅消息）③ 登录（网页授权静默——微信内免登录）。P2 合规触达、P3 沉默用户可达
对话式 Agent（FR-19）服务号对话框 = 移动端最短输入路径：「微信里转发链接，爆款就拆好了」。移动端输入摩擦最小化
官网收款页三层漏斗收款主通道（浏览器/桌面端完成，微信内不收款）；兑换码站外补充。收款合规（无 iOS 虚拟支付约束、无 30% IAP 抽成）
微信小程序（P2）观察项：上线后若移动端数据异常再补；后端 REST 前端无关，沉没成本 ≈ 0。微信内即点即用（远期）
微信 Bot（ClawBot）实验通道：种子用户过渡期保留，不承诺 SLA；15 条指令意图识别逻辑平移至 FR-19。—

改判依据（完整论证见 MD 版 PRD v1.3 附录 B.2）：竞品实证（10 家同类产品 5 家纯网页、收款均在官网）；iOS 虚拟支付约束（小程序虚拟商品必须接虚拟支付且 iOS 走 Apple IAP 抽成 30%，独立官网收款不受此约束）；付费主力工作场景在桌面（长文案编辑/数据看板/批量管理）；「手机发布」与产品形态无关——发布发生在小红书 App，本产品只负责「取走产物」，响应式 H5 完全覆盖。

2.2 为什么不是小程序优先 / App

  • 小程序（原决策，v1.2 改判）：iOS 禁虚拟支付、IAP 30% 抽成、每版审核拖慢迭代、小屏损害编辑与看板体验；核心优势（即点即用+订阅消息）已由服务号三合一覆盖 80%——降为 P2 观察项而非取消。
  • App：下载安装是第一道流失口；单人团队无双端维护带宽；微信生态内传播无法直达。
  • 桌面专属网站（排除「假 Web」形态）：移动端轻交互链路必须覆盖——响应式设计为硬要求，同一代码库自适应。

§3范围

3.1 P0 最小完整旅程

入口条件：微信用户首次打开小程序。
旅程：微信一键登录 → 两步定位引导 → 看到今日专属选题清单 → 选一条「照这个写」→ 观看生产进度 → 收到成品（图文预览+发布文案）→ 发布后登记链接 → 次日看到该笔记的赞藏评数据。
完成证据：用户在「数据」页看到自己已发布笔记的真实回采数据与增量。
关键恢复路径：生产失败的任务可一键重试（见 FR-04 异常）。

§4产品模型

4.1 对象与关系

对象定义与 Bot 版对应
用户微信 openid 唯一标识；与 Bot uid 同一体系映射，两端口径互通。uid
定位赛道 + 人设 + 关键词（数组），每用户一份；驱动评分与仿写。user_profiles（/定位）
选题雷达产出的单条候选：标题/热度/四维评分/仿写角度/人设钩子；按用户专属清单组织，每日一份。topic_list_{date}.json（重方案个人目录）
任务一次生产：选题 → 拆解 → 仿写 → 配图 → 交付；有唯一任务号与状态机。tasks
发布记录任务交付后用户登记的小红书链接 + 回采的指标快照序列。published_url / metrics

4.2 任务状态机（跨端共享，Bot 与小程序一致）

queued 已排队→ rewriting 拆解仿写→ imaging 配图→ delivered 已交付
failed 失败← 任一环节可失败，可重试；重试回 queued

已交付任务追加登记发布链接后进入「已发布」标记态；发布记录的回采不改变任务状态。

4.3 用户旅程图

阶段用户动作系统响应触达
① 进入打开小程序，微信一键登录无定位 → 进引导；有定位 → 进今日选题—
② 定位两步填写人设/赛道/关键词（第一步人设+赛道同屏）保存定位；生成首份专属选题清单（异步）任务完成通知
③ 选题浏览清单，点「照这个写」任务入队，进度页实时刷新生产完成通知
④ 交付预览图文、复制发布文案、存图引导「发布后回来登记」—
⑤ 登记粘贴发布链接关联最近已交付任务，纳入每日回采—
⑥ 复盘打开数据页看赞藏评与增量每日自动回采；日报推送数据日报

§5功能需求

FR-01登录与账号P0
触发
用户首次打开小程序，或本地凭据失效时。
处理
微信一键登录（不弹授权弹窗收集昵称头像）。openid 映射到内部 uid；若该 uid 已有 Bot 使用记录，自动继承其定位、任务、发布记录与成本数据。
结果
登录态静默保持；进入首页时按「有无定位」分流到 FR-02 或 FR-03。
边界
登录失败：展示重试入口，不阻塞浏览空态首页。老用户继承逻辑失败时按新用户处理并提示可联系主理人找回。
FR-02定位引导（Onboarding）P0
触发
登录后无定位记录，用户点击「设置我的定位」。
布局
两步向导（v1.1 依评审 U10/U5 调整），每步一屏，向导期间隐藏底部 Tab 导航，步骤用节点式指示器：① 人设 + 赛道同屏（一句话自我介绍，示例引导文案 + 「一键用示例」；预设旅行方向单选，选中态明确，含自定义输入）→ ② 关键词（1–5 个，逗号分隔，chip 呈现可删）。
规则
与 Bot 口径一致：至少填「人设」或「关键词」一项才能提交；关键词空格/逗号/顿号混输均容忍。提交即保存并触发首份专属清单生成（异步，见 FR-03 抓取态）。
结果
保存定位 → 跳转首页，首页展示「清单生成中」的抓取态；完成后清单卡片流入场。
异常
抓取失败（无候选/服务异常）：首页显示失败原因与「重试抓取」按钮，不回退定位数据。
FR-03今日选题清单（首页）P0
触发
每日进入首页；或用户下拉刷新 / 点击「重新抓取」。
布局
顶部刊头（日期 + 「今日 X 条选题，按你的定位评分」）→ 选题卡片流，默认展示前 5 条，展开加载全部。卡片默认态（评审 U4 信息分级）：标题、热度标签、综合推荐分徽章、最高维标签、按钮「照这个写」；卡片展开态（点卡片展开，首推卡默认展开）：四维评分条（相关/爆点/人设契合/转化，颜色按分值映射见 §6.1）、仿写角度一句话、人设钩子。CTA 主次（评审 U2）：当日综合推荐分最高的 1 条标注「今日首推」徽章、实心按钮，其余统一描边按钮。
规则
① 默认读用户专属清单（重方案：按该用户关键词+人设独立评分）；无专属清单时回退全局清单并明确标注「通用清单 · 设置定位后更准」。
② 每日雷达由系统定时跑（Bot 与小程序共用一次抓取，不重复消耗）；「重新抓取」走按需抓取，相同日期内覆盖个人清单。
③ 卡片展示与 Bot /选题 同源同序；评分低于语义硬门槛的淘汰项不在小程序展示。
④ P1 历史日期切换（近 7 天）与「按主题探索」（门槛放开的探索模式，结果标注「探索模式 · 门槛放开」）。
⑤ 主题探索模式（v1.3 增强，R22）：首页「+ 按关键词探索」——输入任意关键词（无需改定位），调红狐 search API 拉取爆款笔记，返回自选条数（默认 5 条）的内容级卡片：封面缩略（cover）+ 标题 + 作者/粉丝量 + 发布日期 + 互动数（模糊化）+ 综合分徽章；「查看原文」入口（shareInfoLink）先看全文再决定；双动作「照这个写」/「拆解看看」（仅拆解不生产）；相关搜索词 chip（relatedSearches，点击再探索）+ 热门话题标签建议（hotTopics）。
空态
当日无清单：区分「还没生成（去抓取）」「门槛筛后为空（展示漏斗数据：抓取 N → 达标 0，建议放宽关键词）」「抓取失败（重试）」三种，各配专属文案。
FR-04生产任务P0
触发
选题卡点「照这个写」；或历史任务详情点「重试」。
规则
① 确认即建任务入队（同 Bot /确认 N），同一选题可多次生成，任务号区分。
② 进度页展示四阶段步进条：拆解仿写 → 配图 → 交付（文案 + 图文卡片），每阶段完成即点亮；预估时长以「约 1–3 分钟」量级文案呈现，[TBD：实测后校准]。
③ 「换角度」入口：任务页改写仿写角度后重新生产（同 Bot /换角度 N）。
④ 用户离开页面后生产继续；完成靠服务号模板消息（FR-07）召回。
⑤ 「生成视频版」入口（P1，评审 R4 升级）：已交付任务详情页发起，生产端已支持，完成经模板消息通知。
⑥ 失败重试需二次确认（防重复消耗额度；失败额度自动返还，见 FR-10）。
状态与异常
失败任务在「生产」Tab 常驻展示失败原因（文案生成失败/生图通道失败），提供「重试」与「换生图通道」两个动作；重试生成新任务，原任务保留可追溯。
FR-05成品交付P0
触发
任务状态变更为已交付；用户从通知或「生产」Tab 进入。
布局
图文卡片轮播（首图突出，支持单张保存/批量保存到相册）→ 发布文案区（标题+正文+话题标签）→「一键复制全文」→ 交付清单摘要（张数/通道/生成时间）。
规则
① 文案复制保留小红书排版换行；复制成功有明确反馈并引导「发布后回来登记链接，开启数据追踪」。
② 交付消息拆条问题不复存在——小程序内一次呈现全部成品，不占用任何推送配额；推送侧只在完成时发 1 条通知。
③ 发布跟办清单（P1，评审 R6/N4）：交付页提供四步 checklist——复制文案 → 存图 → 去小红书发布 → 回来登记；「已交付未登记」的任务在生产 Tab 置顶提醒。登记率是效果回流的北极星前置指标。
④ 质检徽章与拆解透出（P1，评审 R7）：交付页展示「质检通过」徽章（标题/字数/图片规格）；「拆解笔记」折叠区透出爆款拆解维度与多模态看图标注，让小白理解「为什么这样仿写」。
异常
图片保存到相册需相册权限：拒绝后提供「去设置开启」引导；图片链接过期时支持「重新取图」。
FR-06发布登记与效果看板P0
触发
交付后引导页；或「数据」Tab 点「登记已发布」。
规则
① 粘贴小红书链接（xiaohongshu.com/xhslink.com），校验合法性后关联该用户最近一条未登记的已交付任务；关联关系登记后可解绑重绑（解除前需确认）。
② 每日系统定时回采近 30 天内发布笔记的赞藏评（回采窗口与 Bot 共用配置口径）；数据页展示：赞/藏/评三卡（总量 + 今日增量）与近 30 天趋势。
③ 手动「立即刷新」单条笔记（每次刷新计一次详情抓取消耗，成本记入该用户账本）。
④ 增量日报由服务号模板消息推送（FR-07），数据页为完整看板。
空态/异常
无已发布笔记：空态引导回交付页。单条回采失败不影响其余条目；失败项标注「上次成功数据 + 失败时间」。
FR-07触达通知（v1.3 通道改判：服务号模板消息）P0
模板
① 选题日报：「今日 N 条选题已就绪，前 3 条标题摘要」→ 点击进首页。

触发

三步管线
① 圈选样本→ ② 对齐拆解→ ③ 共性统计→ ④ 生成模板→ ⑤ 喂给仿写生产⇢ ⑤b 回采反写个人适配（P2）
① 自动圈选（默认）：按定位关键词取雷达近 30 天 Top 20；或手动勾选 5–50 篇。
② 统一维度：钩子类型 / 结构骨架 / 情绪曲线 / 标签组合 / 发布时段 / 互动增速形态（回采数据）。
③ 输出各槽位选项分布而非单一答案——例「开头钩子：反常识 71% / 提问 20%」「平均 4.2 段，段均 43 字」。
④ 可填空骨架 + 槽位选项分布 + 原文例证；可保存、命名、分享图片。
⑤ 仿写任务可选「按模板生成」——引用模板骨架而非单篇拆解。
⑤b 模板产出的笔记回采后效果自动标注回模板（「此模板在你的账号上高于你的均值 35%」）——从「市场统计」进化为「个人适配版」。
模板 × 拆解的关系（v1.3 澄清，R22）——不是二选一的悖论，是「骨架层 × 参考层」正交组合：模板 = 语法（及格线：结构不犯错、账号风格一致）；拆解 = 范文（上限：这篇为什么特别爆）。仿写发起页三档模式：
模式生成依据适用
直接仿写（默认）单篇拆解的结构逻辑追单篇锋利感
按模板生成模板骨架，槽位从选项分布采样日常量产、风格一致性
模板 + 参考单篇（推荐）模板骨架 × 指定单篇钩子特化——生成 prompt 分层引用重点内容，兼顾及格线与上限
同质化防御：回采反写后模板为个人账号适配版（随自身数据分化，无「全网同一模板」）；槽位选项分布引入多样性采样；FR-18 AI 味检测兜底。
模板生命周期
building 生成中→ ready 可用→ adapting 个人适配（P2）→ deprecated 已过气（可重提）
保鲜期：模板头部展示「样本时间窗 + 最近验证时间」；超 90 天未验证标注「可能过气」。
额度与边界
一次提炼计 1 次生产额度（FR-10）；样本 <5 篇不允许发起；模板为结构规律，不含原文明文搬运（§3.3 红线）。
FR-17翻红计划（存量笔记翻新）P1v1.3 新增
定位
博主不缺新笔记，缺的是救活已发布的存量。全部竞品都在做「增量生产」，无人做「存量运营」——识别潜力股恰恰需要回采时间序列数据。一篇翻红 ≈ 一篇新爆文，成本远低于写新篇。
算法依据
候选池：已登记回采 ≥14 天、仍在 30 天回采窗口内的笔记。潜力股 = 两条信号同时命中：
信号定义依据
S1 历史验证发布 72h 内赞藏评总量位于该用户全部笔记前 30%（账号内相对分位）内容本体曾被市场验证——排除「内容差」这个不可优化变量，失败原因在「包装」或「时机」
S2 增长停滞近 7 天互动增量 < 2互动归零即退出推荐池；翻新（编辑触发重审与部分再推荐 [Assumption,TBD]）机会成本低
诊断信号（为什么沉了 → 优化方向）： 藏赞比偏高 → 改标题钩子与封面 评赞比偏高 → 换更大流量标签 增速前快后慢 → 全面翻新 对照赛道模板找结构偏离点
数据边界诚实声明：小红书不向第三方开放曝光/点击，算法全部基于账号内相对比较，不做跨账号绝对值判断。
交互逻辑（七步闭环）
① 入口数据页「翻红计划」卡片——有潜力股时红点徽章 +「发现 N 篇潜力股」
② 潜力股列表封面缩略 + 三卡数据 + 诊断标签；「为什么是潜力股」折叠说明（S1/S2 命中详情，算法透明化）
③ 诊断报告历史表现曲线（72h vs 近7天）+ 编辑口吻归因（「藏的人多、赞的人少——内容有用，但标题没让人心动」）+ 与赛道模板偏离点
④ 优化方案新标题 ×3（不同钩子方向）+ 封面建议 + 标签调整建议；全部可编辑，可只采纳部分
⑤ 执行跟办四步 checklist：复制新标题 → 改封面 → 去小红书编辑已发布笔记 → 回来点「已完成编辑」
⑥ 观察期自动延续回采 7 天（复用每日回采，零额外消耗）；「翻红观察中 · 第 N 天」；翻红前基线 vs 翻红后增量双轴呈现
⑦ 结论见效（翻新后 7 天增量 ≥ 翻新前 2 倍）/ 无效；结论推模板消息；见效结构回流 FR-16 模板库
状态机
candidate 候选→ diagnosed 已诊断→ optimizing 优化中→ observing 观察期7天→ verdict 见效/ 无效→ archived 归档
任意状态可「放弃翻新」→ archived（记录原因）。
额度与约束
诊断+方案生成计 1 次生产额度；观察期回采免费（手动刷新按 FR-06 计费）；同一笔记同时仅一条活跃记录；每月发起上限 [TBD：建议免费 2 次/月，付费 8 次/月——防高频编辑触发平台风控]；未登记笔记无法翻新（翻红依赖回采数据，与 FR-05 登记率北极星同向）。

§6界面设计

6.1 设计调性：「旅行编辑部」

用户是旅行自媒体人，产品要给的感受是——「有一位专业编辑每天为我的账号挑选题、写稿、盯数据」，而不是一个冷冰冰的 SaaS 工具。因此整体采用杂志编辑部风格：暖纸底色、衬线刊头、车票式标签、纸质卡片；克制、专业、有人味。拒绝科技感渐变紫与后台仪表盘味。本 PRD 的排版即此调性的示范。

空态插画 + 一句编辑口吻文案（如"今天编辑部还没挑出好题——换个关键词试试"），并永远给出下一步动作按钮。

§7共享规则

7.1 通知策略（跨模块统一）

事件通道与时机降级
选题就绪服务号模板消息，每日雷达完成后（默认 8:00 档）首页红点待读
任务完成 / 失败服务号模板消息，状态变更即时生产 Tab 常驻 + 待读
数据日报服务号模板消息，每日回采后（默认 9:00 档）；仅当日有增量才推数据页查看
翻红观察结论（v1.3）服务号模板消息，观察期满即时数据页翻红报告
授权请求仅价值交换节点弹出，单日单用户 ≤1 次静默跳过

7.2 数据口径（与 Bot 版一致，一处定义）

  • 清单归属：有定位用户读个人专属清单（按其关键词+人设独立评分）；无定位用户读全局清单。个人清单按日覆盖。
  • 回采窗口：仅自动回采近 30 天发布的笔记；超窗笔记保留历史数据，可手动刷新。
  • 成本归属：生产记任务号、雷达记日期、回采记回采批次；单篇成本 = 该任务号全部条目聚合。
  • 同端互斥：同一 uid 同时只用一个活跃通道推送，避免双端重复打扰。

7.3 权限

操作规则
查看/生产/登记仅本人数据；uid 边界硬隔离（清单、任务、发布记录、成本均按 uid 过滤）。
定位修改本人可改，改后次日清单生效，当日的可手动重抓。
发布记录解绑需二次确认；解绑后该笔记停止回采。
