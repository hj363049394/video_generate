## 1 背景与痛点

### 1.1 已确认的事实基础

- **已落地**　生产线：红狐抓取 → 数值 + 语义四维评分 → 仿写 → 图文卡片 → 视频按需生成；多用户重方案（每人按自己的关键词/人设独立评分、独立推送清单）已上线。
- **已落地**　效果回流：`/已发布` 登记发布链接，每日定时回采赞藏评并推送增量日报；成本账本可查单篇花销。
- **已验证**　微信 Bot（ClawBot iLink）单号可服务多用户，但存在 §1.2 三大约束；飞书替代方案已被应用商店驳回（非企业办公类应用）。
- **已确认**　目标用户（v1.3 分层重构，R18）：**核心付费用户 = 腰部个人博主（粉丝 1千–5万，周更 1–3 篇，¥49 主力档）与高频创作者（日更/准日更、账号即副业，¥99 档）**；代运营主理人为高价值延伸（服务 3–10 个客户号，¥199+ 档，效果数据展示是其付费核心理由，MVP 以多账号注册承接、P2 上多客户视图）；素人新手为漏斗层（免费额度 + ¥0.99 体验卡，转化的种子与口碑源）；企业级客户明确不做（B2B 销售周期与单人团队不匹配）。**赛道全面开放，不设类目限制**——关键词订阅与定位机制按用户自定义赛道运作，覆盖全类目。

### 1.2 痛点清单

| 编号 | 痛点 | 描述 | 直接影响 |
|---|---|---|---|
| **P1** | 风控不可承诺 | Bot 账号一旦封号，该号下所有付费用户同时失联，SLA 无法承诺 | 不敢收费，商业化被卡死 |
| **P2** | 推送配额挤占 | 每用户 24h 主动推送约 10 条；一单成品交付拆 6–9 条消息已贴近上限，选题清单、数据日报还要再挤 | 关键通知被丢弃或降级 |
| **P3** | 会话保活依赖 | 会话令牌需用户每天说话续期，沉默用户收不到任何推送——数据日报对沉默用户失效 | 效果回流卖点断链 |
| **P4** | 指令门槛 | 10+ 条指令（`/定位 /选题 /确认 N /换角度 N /已发布 /效果 /成本 …`），小白记不住、不敢用 | 激活与留存受损 |
| **P5** | 消息流不可视 | 选题评分、赞藏评趋势、成品图文全部以纯文本呈现，数据无法沉淀为可回看的看板 | 付费价值感知弱 |

## 2 解决方案与产品形态

### 2.1 形态决策（v1.3 改判，R19）

**决策：以响应式 Web 应用（移动 H5 + 桌面增强，同一 URL 同一代码库）为主入口；认证服务号承担「入口 + 触达 + 登录」三合一基建；官网收款页为收款主通道；小程序降为 P2 观察项。**

| 端 | 定位 | 解决的痛点 |
|---|---|---|
| **响应式 Web**（主） | 创作者主入口：移动端覆盖「刷到→拆解→取走产物」轻交互链路（复制文案/长按存图/提交链接），桌面端承载长文案编辑、数据看板、200MB 视频上传等重交互——付费主力用户的核心工作场景 | P4 零指令门槛、P5 可视化、桌面专业体验、免发版审核 |
| **认证服务号** | 三合一基建：① 入口（自定义菜单→H5；模板消息点击→H5 交付页）② 触达（模板消息推送任务完成/数据日报，对沉默用户覆盖强于小程序订阅消息）③ 登录（微信网页授权 snsapi_base 静默拿 openid——微信内免登录体验，追平小程序） | P2 合规触达、P3 沉默用户可达 |
| **对话式 Agent**（服务号对话框，FR-19） | 移动端最短输入路径：「微信里转发链接，爆款就拆好了」；复用 ClawBot 指令意图识别逻辑 | 移动端输入摩擦最小化 |
| **官网收款页** | 三层漏斗收款主通道（浏览器/桌面端完成，微信内不收款）；兑换码为站外补充；小程序虚拟支付为远期可选 | 收款合规（不受 iOS 虚拟支付约束、无 30% IAP 抽成） |
| **微信小程序**（P2） | 观察项：上线后若数据显示移动端占比/流失异常再补；后端 REST 架构前端无关，随时可加，沉没成本 ≈ 0 | 微信内即点即用（远期） |
| **微信 Bot**（ClawBot） | 实验通道：种子用户过渡期保留，不承诺 SLA，不进付费话术；其 15 条指令的意图识别逻辑平移至 FR-19 | — |

改判依据（完整分析见附录 B.2）：竞品实证（10 家同类产品 5 家纯网页、收款均在官网）、iOS 虚拟支付约束（小程序内虚拟商品必须接虚拟支付且 iOS 走 Apple IAP 抽成 30%，而独立官网收款不受此约束）、目标用户工作场景（付费主力为腰部博主/高频创作者/代运营，长文案编辑与数据看板在桌面端体验碾压手机）、产品职责边界（发布动作发生在小红书 App / 创作服务平台，不经由本产品——「手机发布」的用户习惯与产品形态无关）。

### 2.2 为什么不是小程序优先 / App（v1.3 改判后保留的排除项）

- **小程序（v1.2 原决策，v1.3 改判）**：iOS 禁虚拟支付、IAP 30% 抽成、每版审核拖慢迭代、小屏损害长文案编辑与数据看板体验；小红书生态内分享小程序码受限。小程序的核心优势（微信内即点即用 + 订阅消息）已由「服务号三合一」覆盖 80%，其余 20% 的体验差不足以抵消三座成本山。降为 P2 观察项而非取消——后端前端无关，数据异常随时回补。
- **App**：下载安装是第一道流失口；单人团队无 iOS/Android 双端维护带宽；微信生态内传播无法直达。
- **桌面专属网站**（排除「假 Web」形态）：移动端轻交互链路（提交链接/取产物）必须覆盖——目标用户在手机上刷到爆款、在微信里收通知。响应式设计为硬要求，移动端布局与桌面布局同一代码库自适应。

### 2.3 触达策略（v1.3 修订：服务号主通道模型）

> **v1.3 改判说明（R19）**：小程序降为 P2 后，原「小程序订阅消息主通道」整体替换为「服务号模板消息主通道」。优势：用户关注服务号一次即可长期触达（不需要反复授权），沉默用户覆盖优于小程序订阅消息的一次性授权模型——原 P3 约束从「缓解」升级为「基本消除」。前提：服务号需完成企业主体认证 `[TBD：认证时效与模板类目审批]`。

| 通道 | 角色 | 适用 |
|---|---|---|
| **服务号模板消息**（主） | 事件触达：任务完成、选题日报、数据日报、翻红观察结论（FR-17）；点开直达 H5 对应页 | 全量已关注用户；关注一次长期有效 |
| **服务号客服消息**（对话） | FR-19 对话式 Agent 的即时回复通道：用户发消息后 48h 窗口内可回复 `[TBD：接口条数限制按最新文档验证]` | 对话式交互（提交链接/追问打磨） |
| **站内待读**（兜底） | 首页红点 + 角标计数，打开必达 | 未关注服务号 / 推送失败时的降级，保证信息不丢 |
| **邮件**（辅助） | 桌面端用户的异步通知补充 | 付费用户可选配置 |

**授权收集策略**：服务号关注引导固定在价值交换节点——提交首个任务后（关注以接收完成通知）、查看数据页时（关注以接收日报）；**绝不弹窗轰炸，单日单用户最多引导 1 次**。未关注用户全部降级站内待读。

## 3 范围

### 3.1 P0 最小完整旅程

- **入口条件**：用户首次访问 Web 应用（手机浏览器 / 微信内打开 / 桌面浏览器三入口之一）。
- **旅程**：登录（微信内静默授权 / 手机号验证码） → 三步定位引导 → 看到今日专属选题清单 → 选一条「照这个写」→ 观看生产进度 → 收到成品（图文预览 + 发布文案）→ 按跟办清单发布 → 回来登记链接 → 次日看到该笔记的赞藏评数据。
- **完成证据**：用户在「数据」页看到自己已发布笔记的真实回采数据与增量。
- **关键恢复路径**：生产失败的任务可一键重试（FR-04）；抓取失败回落昨日清单（FR-03）；推送失败降级站内待读（FR-07）。

### 3.3 明确不做

- 前端不做账号矩阵管理（P2 主理人多客户视图承接）、不做评论代回复、不做粉丝画像分析——均属远期范围。
- **直接生图**（Bot 端 `/生图` 工具性功能）不纳入——与核心旅程无关（v1.1 补记）。
- **自动发布到小红书**不做——平台无开放发布接口，产品定位为「生产辅助 + 数据回流」，搬运环节用跟办清单优化体验（FR-05）；这也是「人工过稿」战略纪律的要求（R21，附录 B.4）。
- **搬运原素材成片**不做（v1.2 补记）——多平台拆解仅提取「结构逻辑 + 文案」用于原创仿写，生成视频一律使用自产图卡 + TTS 配音，不引用原视频画面/音频/字幕成片。
- **抖音客户端硬爬取**不做（v1.2 补记）——不做反爬对抗；抖音链接走第三方解析 `[TBD：服务商选型]`，解析失败一律引导「上传视频拆解」通道（FR-14）。

## 4 产品模型

### 4.1 对象与关系

| 对象 | 定义 | 与 Bot 版对应 |
|---|---|---|
| **用户** | 微信 openid 唯一标识；与 Bot uid 同一体系映射，两端口径互通 | `uid` |
| **定位** | 赛道 + 人设 + 关键词（数组），每用户一份；驱动评分与仿写 | `/定位` 用户档案 |
| **选题** | 雷达产出的单条候选：标题/热度/四维评分/仿写角度/人设钩子；按用户专属清单组织，每日一份 | 重方案个人清单 |
| **任务** | 一次生产：选题 → 拆解 → 仿写 → 配图 → 交付；有唯一任务号与状态机；记录来源平台（小红书/B站/YouTube/抖音/上传，v1.2） | `tasks` |
| **发布记录** | 任务交付后用户登记的小红书链接 + 回采的指标快照序列 | 发布登记 + 效果回采 |
| **翻新记录**（v1.3 新增） | 一次存量笔记翻新：潜力股笔记 + 诊断报告 + 优化方案 + 7 天观察结论；有唯一翻新号与状态机（FR-17） | 新增 |
| **模板**（v1.3 新增） | 爆款规律引擎产出：可填空骨架 + 槽位选项分布 + 例证 +（随回采积累的）个人适配标注；有唯一模板号与生命周期状态（FR-16） | 新增 |
| **额度**（v1.1 新增） | 用户当日在各维度可消耗的用量上限与余量 | 新增（Bot 版无） |

### 4.2 任务状态机（跨端共享，Bot / Web / 对话式 Agent 一致）

```
queued 已排队 → rewriting 拆解仿写 → imaging 配图 → delivered 已交付
                      │（任一环节可失败）
                      └──→ failed 失败（可重试；重试生成新任务回 queued，原任务保留可追溯）
```

已交付任务追加登记发布链接后进入「已发布」标记态；发布记录的回采不改变任务状态。视频生成为已交付任务派生的子任务，独立计号、独立计费（FR-04）。

### 4.3 用户旅程

| 阶段 | 用户动作 | 系统响应 | 触达 |
|---|---|---|---|
| ① 进入 | 三入口之一打开 Web 应用（微信内静默授权 / 浏览器验证码登录） | 无定位 → 进引导；有定位 → 进今日选题 | — |
| ② 定位 | 三步填写赛道/人设/关键词 | 保存定位；生成首份专属选题清单（异步） | 任务完成通知 |
| ③ 选题 | 浏览清单，点「照这个写」 | 额度校验 → 任务入队，进度页实时刷新 | 生产完成通知 |
| ④ 交付 | 按跟办清单：复制文案、存图、发布 | 引导「发布后回来登记」 | — |
| ⑤ 登记 | 粘贴发布链接 | 关联最近已交付任务，纳入每日回采 | — |
| ⑥ 复盘 | 打开数据页看赞藏评与增量 | 每日自动回采；日报推送 | 数据日报 |

### 4.4 用量额度模型（v1.1 新增，评审 N2）

> **为什么是 P0**：每个用户的消耗是真实货币（雷达搜索 + LLM 评分 + 生图，人均几分钱/天起）。上线若不限量，成本无上界，商业化前提不成立。定价金额可以后定，**额度机制不能后定**。

- **额度维度**：每日选题查看条数、每日生产次数。免费用户数值 `[TBD：随定价评审确定]`，付费用户提升或解除。
- **闸门位置**：服务端校验，前端仅做展示与引导（详见 §7.4 共享规则）。
- **公平性规则**：生产失败自动返还额度；同一任务的重试不重复扣额。

## 5 功能需求

### FR-01 登录与账号 `P0`

- **触发**：用户首次访问 Web 应用，或登录态失效时。
- **处理**（v1.3 双通道登录）：
  1. **微信内打开**（服务号菜单/模板消息/会话分享进入）：微信网页授权 snsapi_base **静默登录**——无感知拿 openid，体验追平小程序原生；openid 映射到内部 uid。
  2. **浏览器/桌面端打开**：手机号 + 验证码登录；已关注服务号的用户可在登录页展示服务号二维码引导关注（获得推送能力）。
  3. 若该 uid 已有 Bot 使用记录，自动继承其定位、任务、发布记录与成本数据。
- **结果**：登录态保持（token 有效期与续期策略见技术方案）；进入首页时按「有无定位」分流到 FR-02 或 FR-03。
- **边界**：登录失败展示重试入口，不阻塞浏览空态首页；老用户继承逻辑失败时按新用户处理并提示可联系主理人找回；同一 uid 的微信通道与手机号通道可绑定合并（「我的 → 账号与绑定」）。
- **注销**（v1.1，评审 N3）：见 FR-11。

### FR-02 定位引导（Onboarding） `P0`

- **触发**：登录后无定位记录，用户点击「设置我的定位」。
- **布局**：三步向导，**每步一屏、每屏一个焦点**（v1.1 修正与线框一致）：① 选赛道（预设旅行方向单选 + 自定义输入）→ ② 写人设（一句话自我介绍 + 示例引导）→ ③ 填关键词（1–5 个，逗号分隔，chip 呈现可删）。
- **交互规则**（v1.1，评审 U5/U10）：
  - 向导页**隐藏底部 tabbar**，防中途跳走破坏任务闭环；
  - 步骤指示用「节点 + 连线」可视化进度；
  - 赛道标签为单选，选中态需在设计稿明示；
  - 人设步骤提供**「一键用示例开始」**——填入完整示例，小白可直接改两个字提交。
- **规则**：与 Bot 口径一致——至少填「人设」或「关键词」一项才能提交；关键词空格/逗号/顿号混输均容忍。提交即保存并触发首份专属清单生成（异步）。
- **结果**：保存定位 → 跳转首页，首页展示「清单生成中」抓取态；完成后清单卡片流入场。
- **异常**：抓取失败（无候选/服务异常）显示失败原因与「重试抓取」，不回退定位数据。

### FR-03 今日选题清单（首页） `P0`

- **触发**：每日进入首页；或用户下拉刷新 / 点击「重新抓取」。
- **布局**：顶部刊头（日期 + 余量提示 +「今日 X 条选题，按你的定位评分」）→ 选题卡片流（默认展示前 5 条，展开加载全部）→ 每卡按 §6.4 信息分级规则渲染。
- **规则**：
  1. 默认读**用户专属清单**（重方案：按该用户关键词+人设独立评分）；无专属清单时回退全局清单并明确标注「通用清单 · 设置定位后更准」。
  2. 每日雷达由系统定时跑（Bot 与 Web 端共用一次抓取，不重复消耗）；「重新抓取」走按需抓取，相同日期内覆盖个人清单。
  3. 卡片展示与 Bot `/选题` 同源同序；低于语义硬门槛的淘汰项不在前端展示。
  4. **信息分级**（v1.1，评审 U4）：卡片默认层 = 标题 + 热度 + 综合分徽章 + 最高维标签 + CTA；四维评分条、仿写角度、人设钩子折叠进「详情」展开层。首屏可见卡片 ≥3 条。
  5. **CTA 主次**（v1.1，评审 U2）：综合推荐分最高的 1 张卡为「今日首推」（实心 CTA + 首推徽章），其余统一描边 CTA。
  6. P1：历史日期切换（近 7 天）与「按主题探索」。
- **主题探索模式**（P1，v1.3 增强，R22）：首页「+ 按关键词探索」——输入任意关键词（无需修改定位），调红狐 search API 按时间范围（默认近 30 天）拉取爆款笔记，返回**自选条数（默认 5 条，最多 20 条）**的探索卡片流：
  1. **卡片为内容级展示**（区别于每日清单的摘要级）：封面缩略图（红狐 `cover` 字段）+ 标题 + 作者（昵称/粉丝量）+ 发布日期 + 互动数（赞/藏/评，模糊化展示同 §6.4 口径）+ 综合评分徽章；结果标注「探索模式 · 门槛放开」。
  2. **「查看原文」入口**：卡片提供原文链接（`shareInfoLink`）——用户先看全文再决定，不强制盲选。
  3. **双动作**：「照这个写」（进 FR-04 生产，额度校验同常）与「拆解看看」（仅拆解不生产，输出拆解报告，计轻量额度 `[TBD]`）。
  4. **相关搜索推荐**（v1.3，R22）：探索结果页尾部展示红狐 `relatedSearches` 相关搜索词 chip，点击即以该词重新探索——「换个近义词再看看」的发现循环；`hotTopics` 热门话题作为话题标签建议带入生产。
  5. 探索消耗计入按需抓取（同 FR-03「重新抓取」口径），成本记入用户账本。
- **空态**：区分三种并各配专属文案与动作——「还没生成（去抓取）」「门槛筛后为空（展示漏斗数据：抓取 N → 达标 0，建议放宽关键词）」「抓取失败（重试）」。
- **降级**（v1.1，评审 N5）：抓取服务异常时**回落展示昨日清单并显著标注**「数据为昨日 · 抓取暂时不可用」，不白屏。

### FR-04 生产任务 `P0`（视频生成为 `P1`）

- **触发**：选题卡点「照这个写」；或历史任务详情点「重试」。
- **规则**：
  1. 确认即**服务端额度校验**（FR-10）→ 建任务入队（同 Bot `/确认 N`）；同一选题可多次生成，任务号区分。
  2. 进度页四阶段步进：拆解仿写 → 配图 → 交付（文案 + 图文卡片），每阶段完成即点亮；预估时长以「约 1–3 分钟」量级文案呈现 `[TBD：实测后校准]`。
  3. 「换角度」入口：任务页改写仿写角度后重新生产（同 Bot `/换角度 N`）。
  4. 用户离开页面后生产继续；完成靠服务号模板消息（FR-07）召回。
- **失败处理**：失败任务在「生产」Tab 常驻展示失败原因（文案生成失败/生图通道失败），提供「重试」与「换生图通道」两个动作；**重试前二次确认**（防重复消耗额度）；重试生成新任务，原任务保留可追溯。
- **视频笔记生成**（v1.1 升 P1，评审 R4）：已交付任务详情页提供「生成视频版」入口——复用图文素材与口播文案生成视频；完成走模板消息通知；独立子任务计号计费。生产端能力已上线，本项为前端接线。

### FR-05 成品交付 `P0`（跟办清单/拆解/质检为 `P1`）

- **触发**：任务状态变更为已交付；用户从通知或「生产」Tab 进入。
- **布局**：质检徽章区（P1）→ 图文卡片轮播（首图突出，支持单张/批量保存到相册）→ 发布文案区（标题 + 正文 + 话题标签）→「一键复制全文」→ 交付清单摘要（张数/通道/生成时间）→ 发布跟办清单（P1）。
- **规则**：
  1. 文案复制保留小红书排版换行；复制成功有明确反馈并引导「发布后回来登记链接，开启数据追踪」。
  2. 交付一次呈现全部成品，**不占用任何推送配额**；推送侧只在完成时发 1 条通知。
  3. **发布跟办清单**（v1.1，评审 N4/R6）：交付页四步 checklist——① 复制文案 → ② 保存图片 → ③ 打开小红书发布 → ④ 回来登记链接。未登记任务在「生产」Tab 置顶提醒条；交付 48h 未登记发 1 次提醒通知 `[TBD：频次以防打扰为准]`。**登记率是效果回流的北极星前置指标**。
  4. **质检徽章**（v1.1，评审 R7）：交付时展示「质检通过」徽章（标题党检测/字数/图片规格），失败项给改进建议——付费信任信号。
  5. **拆解笔记折叠区**（v1.1，评审 R7）：可展开查看本篇的爆款拆解逻辑（拆解维度 + 看图拆解标注），让小白学到「为什么这样仿写」。
- **异常**：相册权限被拒提供「去设置开启」引导；图片链接过期支持「重新取图」；内容安全拦截见 FR-11。

### FR-06 发布登记与效果看板 `P0`

- **触发**：交付后引导页；或「数据」Tab 点「登记已发布」。
- **规则**：
  1. 粘贴小红书链接（`xiaohongshu.com`/`xhslink.com`），校验合法性后关联该用户最近一条**未登记的已交付任务**；解绑需二次确认，解绑后该笔记停止回采。
  2. 每日系统定时回采近 30 天内发布笔记的赞藏评（回采窗口与 Bot 共用配置口径）；数据页展示：赞/藏/评三卡（总量 + 今日增量）与近 30 天趋势。
  3. 手动「立即刷新」单条笔记（计一次详情抓取消耗，成本记入该用户账本）。
  4. **数据叙事三态**（v1.1，评审 U6）：每条笔记按趋势标注「冲榜中 / 平稳 / 长尾」口语化标签 `[TBD：阈值随上线数据校准]`；增量色正=墨绿、负=珊瑚、零=纸灰。
  5. 增量日报由服务号模板消息推送（FR-07），数据页为完整看板。
- **空态/异常**：无已发布笔记时空态引导回交付页；单条回采失败不影响其余条目，失败项标注「上次成功数据 + 失败时间」。

### FR-07 触达通知 `P0`（v1.3 通道改判：服务号模板消息）

- **模板**：
  1. **选题日报**：「今日 N 条选题已就绪，前 3 条标题摘要」→ 进首页。
  2. **任务完成**：「你的笔记已生成（任务号）」→ 进交付页。
  3. **数据日报**：「昨日你的笔记 +X 赞 +Y 藏」→ 进数据页。
  4. **翻红结论**（v1.3，FR-17）：「翻新观察结束：《标题》见效/无效」→ 进翻红报告页。
- **规则**：
  1. **主通道 = 服务号模板消息**：已关注用户一次关注长期可触达（对沉默用户覆盖优于小程序订阅消息的一次性授权模型）。关注引导固定在价值交换节点——提交首个任务后、查看数据页时；**绝不弹窗轰炸，单日单用户最多引导 1 次**。
  2. 未关注 / 推送失败：降级为站内待读（首页红点 + 角标计数），下次打开必达。
  3. 推送内容包含核心信息量（标题/增量数字），即使不点开也有价值。
  4. 高价值事件（如某篇笔记数据突增、翻红见效）用一次性通知强化「值得回来」的钩子，不与例行日报混发。
  5. 模板文案字段预留可替换，以微信审核通过版本为准 `[TBD：模板类目审批]`。
- **与 Bot 的关系**：Web 用户默认不再走 Bot 推送；未迁移老用户维持 Bot 通道直至引导迁移完成。

### FR-08 成本明细页 `P1`

- **触发**：「我的」Tab → 成本明细；或任务详情 →「本篇花了多少」。
- **规则**：
  1. 单篇视图：该任务各环节用量与折算金额（提示词字符、生图张数、详情抓取次数）；汇总视图：近 7 天用量与金额。
  2. 金额为按配置单价的估算值，页面固定文案「按当前单价估算，以账单为准」；未配置单价时仅展示用量。
  3. 付费用户成本透明是信任卖点；免费用户仅展示用量不展示金额。
  4. 与 FR-10 额度的关系：**额度是约束（还能用多少），成本是透明度（已经花了多少）**——两页互链但不合并。

### FR-09 直发仿写 `P1`

- **触发**：首页「+ 自由仿写」：粘贴小红书笔记链接，或直接输入首行标题 + 正文。
- **规则**：与 Bot 拉模式同源——链接 → 抓详情（视频笔记提取口播文案）→ 按用户定位仿写；纯文本 → 直接生产。生产共用 FR-04 任务流，受 FR-10 额度约束。
- **异常**：链接无效/抓取失败给出明确原因；视频提文案超时降级为仅看图拆解并标注。
- **多平台扩展**（v1.2）：本 FR 的链接输入升级为多平台识别（小红书/B站/YouTube/抖音）+ 视频文件上传，见 FR-14。

### FR-10 用量额度 `P0`（v1.1 新增）

- **触发**：用户触发需计额度的动作（查看超量选题、发起生产）时校验。
- **规则**：
  1. **闸门在服务端**：生产入队、清单下发前校验余量；前端仅做余量展示与超额引导，不承担校验。
  2. **免费额度**：每日可查看选题条数 X、每日生产次数 Y `[TBD：随定价评审]`；超量部分——选题不再下发（展示「今日免费额度已用完，升级查看全部 N 条」），生产按钮置灰并引导升级。
  3. **额度展示**：首页刊头轻量余量条（「今日还可写 2 篇」）；「我的」页展示完整额度与重置时间。
  4. **重置**：每日 0 点（北京时间）重置。
  5. **公平性**：生产失败自动返还额度；同一任务重试不重复扣额；任务取消（如有）返还额度。
  6. **付费关系**：升级后额度提升或解除 `[TBD：定价与档位]`；额度规则一处定义（§7.4），FR-03/FR-04/FR-08 引用不重复定义。

### FR-11 内容安全与合规 `P0`（v1.1 新增）

  2. 图片安全沿用生图通道自带审核 `[Assumption, TBD：验证各通道审核覆盖]`，Web 端交付前不再重复检测。

- **账号注销**：「我的 → 注销账号」，二次确认 + 数据范围说明（任务/发布记录/成本记录清除 `[TBD：保留期]`）；注销后 openid 解绑。
- **隐私协议/用户协议**：首次启动展示；「我的」页常驻入口。

### FR-14 多平台拆解输入 `P1`（v1.2 新增）

- **触发**：FR-09「自由仿写」入口粘贴 B站 / YouTube / 抖音视频链接；或上传本地视频文件。
- **规则**：
  1. **链接通道**：系统自动识别平台——小红书（红狐，现状）/ B站 / YouTube（抓取元数据 + 字幕 + 关键帧）/ 抖音（第三方解析 `[TBD：服务商选型]`）；解析失败引导走上传通道。
  2. **上传通道**（全平台兜底，合规首选）：用户上传原视频 → 服务端抽音轨转写（ASR）+ 关键帧抽取 → 进入同一拆解管线；时长上限 10 分钟 `[TBD：随成本与体验评估]`。
  3. **拆解产物与小红书拉模式同构**：结构逻辑 + 仿写角度 + 口播文案；下游仿写/图卡/视频生产线全复用，不因平台分叉。
  4. 无字幕视频自动 ASR 兜底转写；YouTube 通道依赖海外网络出口 `[TBD：部署拓扑]`。
  5. **额度与成本**：计入 FR-10 生产次数；ASR / 看图成本计入该用户成本账本（FR-08 可见）。
  6. **合规红线**：仅拆解「结构与文案」用于原创仿写；不搬运、不引用原视频画面/音频成片（§3.3）。
- **结果**：拆解完成后与 FR-09 拉模式同流——按用户定位仿写 → 生产（FR-04）→ 交付（FR-05）。

### FR-16 爆款规律引擎（赛道模板提炼） `P1`（v1.3 新增）

> **定位**：把「单篇拆解」升级为「多篇聚合拆解」——单篇爆款含大量偶然因素，多篇同赛道爆款的共性结构才是可迁移规律。产出可复用模板，并随用户回采数据进化为「个人适配版」。竞品分析确认全市场无此能力（需要雷达圈选 + 回采反写两个前置资产，见附录 B.3）。

- **触发**：「选题」页 →「提炼赛道模板」；或「数据」页 →「把爆款变成模板」。
- **输入（圈选样本）**：
  1. **自动圈选**（默认）：按用户当前定位关键词，取雷达近 30 天内综合评分 Top 20 爆款笔记 `[TBD：样本量下限，首版建议 ≥10 篇，不足时提示放宽关键词]`。
  2. **手动圈选**：用户在选题历史/已回采笔记中勾选 5–50 篇。
- **处理（三步管线）**：
  1. **对齐拆解**：每篇样本按统一维度拆解——钩子类型（反常识/提问/数字承诺/悬念…）、结构骨架（段落数/每段职能/节奏）、情绪曲线（起伏点位）、话题标签组合、发布时段、互动增速形态（回采数据，仅已登记笔记有）、**封面风格聚类**（v1.3，R22：红狐 `cover` 封面图多模态看图分析——构图/色调/文字密度分型，官方 skill 已验证此用法）。
  2. **共性统计**：输出各槽位的**选项分布**而非单一答案——例「开头钩子：反常识 71% / 提问 20% / 其他 9%」「平均 4.2 段，段均 43 字」「100% 在末段带互动引导」「封面 65% 为大字报式」。
  3. **模板生成**：LLM 综合统计结果 + 原文例证，产出**可填空骨架**（槽位 = 选题主题 / 人设视角 / 每段要点 / 互动引导），每个槽位附选项分布与原文例句。
- **输出与闭环咬合**：
  1. **模板可保存、可命名、可分享为图片**（分享风格同 FR-12）。
  2. **喂给生产（三种生成模式，v1.3 澄清，R22）**——模板与直接拆解仿写**不是二选一的悖论，是「骨架层 × 参考层」的正交组合**：模板提供赛道统计规律（及格线保障——结构不犯错、账号风格一致，适合日常量产）；单篇拆解提供个案锋利特化（上限突破——这篇为什么特别爆的独特钩子，适合重点内容/追热点）。类比写作教学：模板是「语法」，拆解参考是「范文」。仿写任务（FR-04/FR-09）发起页提供三档：

| 模式 | 生成依据 | 适用 |
|---|---|---|
| **直接仿写**（默认，现状） | 单篇拆解的结构逻辑 | 追单篇锋利感 |
| **按模板生成** | 模板骨架，槽位从选项分布采样 | 日常量产、账号风格一致性 |
| **模板 + 参考单篇**（推荐档） | 模板骨架 × 指定单篇的钩子/情绪特化——生成 prompt 分层引用（骨架层用模板、风格层用拆解） | 重点内容，兼顾及格线与上限 |

  **同质化防御**（模板的真正风险不是与拆解冲突，而是趋同）：模板经回采反写（⑤b）后是**个人账号适配版**——每个用户的模板随自身数据分化，不存在「全网同一模板」；槽位选项分布本身引入多样性采样；FR-18 AI 味检测兜底；人工过稿纪律（附录 B.4）不变。
  3. **回采反写个人适配**（P2 随数据积累开放，FR-16⑤b）：用该模板产出的笔记 → 回采 → 效果自动标注回模板——「此模板在你的账号上 CTR 代理值高于你的均值 35%」；模板从「市场统计」进化为「个人适配版」。
  4. **保鲜期标注**：模板头部展示「样本时间窗 + 最近验证时间」；超 90 天未回采验证的模板标注「可能过气，建议重新提炼」。
- **模板生命周期状态机**：
```
building 生成中 → ready 可用 → adapting 个人适配中（P2） → deprecated 已过气（可重新提炼）
```
- **额度与计费**：一次模板提炼计 1 次生产额度（FR-10）；对齐拆解与 LLM 统计成本记入该用户成本账本（FR-08 可见）。
- **边界**：样本 <5 篇不允许发起（提示「爆款样本不足」）；同关键词 24h 内重复提炼给出确认拦截；模板内容为结构规律，不含原文明文搬运（合规红线同 §3.3）。

### FR-17 翻红计划（存量笔记翻新） `P1`（v1.3 新增）

> **定位**：博主不缺新笔记，缺的是救活已发布的存量。全部竞品都在做「增量生产」，无人做「存量运营」——而识别潜力股恰恰需要回采时间序列数据，这是本产品数据闭环的独占延伸。一篇翻红的收益 ≈ 一篇新爆文，成本远低于写新篇。

#### 17.1 算法依据

**候选池**（进入翻红视野的前提）：已登记回采 ≥14 天、且当前仍在自动回采窗口内（近 30 天发布）的笔记。

**潜力股识别信号**（两条同时命中即标记为「潜力股」）：

| 信号 | 定义 | 算法依据 |
|---|---|---|
| **S1 历史验证** | 发布 72h 内赞藏评总量位于该用户**全部笔记的前 30%**（账号内相对分位，跨账号不比较） | 内容本体曾被市场验证有吸引力——排除了「内容差」这个不可优化变量，失败原因更可能在「包装」（标题/封面/标签）或「时机」 |
| **S2 增长停滞** | 近 7 天互动增量 < 2（赞藏评合计） | 互动归零即退出推荐池——小红书笔记依赖互动信号续推，停滞笔记已沉底，翻新（编辑触发重新审核与部分再推荐 `[Assumption, TBD：平台再推荐机制验证]`）的机会成本低 |

**诊断信号**（对潜力股做「为什么沉了」的定性归因，指导优化方向）：

| 信号 | 计算 | 解读 → 优化方向 |
|---|---|---|
| **藏赞比** | 收藏数 ÷ 点赞数 | 比值显著高于账号均值（如 >1.5 倍）→ 工具型内容「有用但不心动」→ 优先改**标题钩子与封面**（把「有用」说得更诱人） |
| **评赞比** | 评论数 ÷ 点赞数 | 比值高 → 话题性强但传播面窄 → 优化**话题标签**（换更大流量的相关标签）与结尾互动引导 |
| **初期增速形态** | 72h 互动曲线斜率 | 前快后慢（爆发即止）→ 吃到了首推但没进下一级流量池 → 全面翻新；匀速缓慢 → 长尾潜力 → 仅调标题 |
| **内容类型** | 图文/视频、字数、图数 | 对照 FR-16 赛道模板的共性统计 → 找出与赛道爆款结构的偏离点（如「你的爆款开头都是反常识型，这篇用了平铺直叙」） |

> **数据边界诚实声明**：小红书不向第三方开放笔记曝光量/点击率，回采仅有赞藏评——因此本算法全部基于**账号内相对比较**（自身分位、自身均值、自身历史形态），不做跨账号绝对值判断。若未来回采通道支持浏览量 `[TBD：红狐能力验证]`，诊断精度可升级。

#### 17.2 交互逻辑（七步闭环）

```
① 入口      数据页「翻红计划」卡片（有潜力股时显示红点徽章 + 「发现 N 篇潜力股」）
   ↓
② 潜力股列表  卡片流：笔记封面缩略 + 三卡数据 + 诊断标签（藏赞比偏高/评赞比偏高/增速前快后慢…）
   ↓           「为什么是潜力股」折叠说明（S1/S2 命中详情，透明化算法依据）
③ 诊断报告   点选一篇 → 报告页：历史表现曲线（72h vs 近7天）+ 归因解读（编辑口吻，如
   ↓           「这篇藏的人多、赞的人少——内容很有用，但标题没让人心动」）+ 与赛道模板的偏离点
④ 优化方案   系统生成：新标题 ×3（不同钩子方向）+ 封面建议（风格/文案方向，不直接生图，
   ↓           生图走正常生产额度）+ 话题标签调整建议。全部可编辑，用户可只采纳部分
⑤ 执行跟办   四步 checklist（同 FR-05 跟办模式）：① 复制新标题 → ② 按建议改封面 →
   ↓           ③ 去小红书编辑已发布笔记 → ④ 回来点「已完成编辑」
⑥ 观察期    系统自动延续回采 7 天（复用每日回采，无额外消耗）；观察期内卡片标注
   ↓           「翻红观察中 · 第 N 天」；期间增量以「翻红前基线 vs 翻红后增量」双轴呈现
⑦ 结论      观察期满自动生成结论卡：「见效」（翻新后 7 天增量 ≥ 翻新前 7 天增量的 2 倍）/
              「无效」（未达阈值）；结论推送一条模板消息；见效笔记的结构特征回流 FR-16 模板库
              （「你账号验证过的有效结构」）
```

**翻新记录状态机**：

```
candidate 候选（命中S1+S2）→ diagnosed 已诊断 → optimizing 待执行/优化中（用户编辑方案）
    → observing 观察期（7天）→ verdict 已见效 / 无效 → archived 已归档
    └── 任意状态可「放弃翻新」→ archived（放弃原因记录：不想改/笔记已删/其他）
```

**约束规则**：
- 同一篇笔记同时只有一条活跃翻新记录；观察期内不允许再次发起。
- 每用户每月翻新发起上限 `[TBD：随定价评审，机制参考 FR-10]`——防止高频编辑触发平台风控 `[Assumption：频繁编辑已发布笔记可能有风险，保守设限]`。
- 笔记在观察期内被用户删除/解绑 → 翻新记录自动归档，结论标注「笔记已移除」。

#### 17.3 额度与计费

- **诊断 + 优化方案生成**计 1 次生产额度（FR-10 口径）；LLM 诊断与标题生成成本入成本账本（FR-08）。
- **观察期回采免费**——复用每日定时回采，不产生额外抓取消耗（仅当用户手动「立即刷新」时按 FR-06 计一次详情抓取）。
- **封面重生成**若走生图通道，独立计费（同 FR-04 生图规则）。

#### 17.4 边界与异常

- 无潜力股时空态：「最近没有沉底的潜力股——持续发布并登记，14 天后这里会出现可翻新的笔记」+ 引导去选题页。
- 回采数据不足 14 天的笔记不进入候选池（诊断无依据）。
- 用户未登记发布链接的笔记无法翻新——「翻红依赖回采数据」本身就是登记行为的价值闭环之一（与 FR-05 登记率北极星指标同向）。
- 平台侧编辑已发布笔记的规则变化（如禁止修改）→ 全量功能降级为「翻新建议报告」（只读），保留诊断价值。

### FR-18 AI 味检测与去 AI 味改写 `P1`（v1.3 新增）

> **定位**：政策联动的防御性刚需——小红书已处置 120 万+ AI 托管账号并治理「AI 批量同质化内容」（附录 B.1）；博主的真实焦虑是「被限流」。本功能与「人工过稿」产品哲学同构（R21 纪律②），是合规姿态的产品化。

- **触发**：任务交付时**自动附带**评分（不额外扣额度）；「我的 → AI 味检测」可对用户粘贴的任意文本手动检测（计入轻量额度 `[TBD]`）。
- **评分模型（AI 痕迹评分 0–100，越高越像 AI）**：
  1. **可量化信号**（规则计算）：句长方差（AI 文本句长均质）、连接词密度（「首先/总之/其次」类）、段落长度均质度、emoji 分布节奏、标点多样性。
  2. **语义信号**（LLM 判断）：口语化程度、个人化细节密度（真实经历词 vs 通用描述）、「人味」表达（语气词/不完美句式/情绪起伏）。
  3. 综合权重 `[TBD：上线后用真实人写/AI 文本对校准]`。
- **档位与动作**：

| 档位 | 分值 | 展示与动作 |
|---|---|---|
| 安心 | <30 | 绿色徽章「读起来像你写的」；无强制动作 |
| 建议改 | 30–60 | 沙金徽章 + 高危片段**划线标注**（指出具体哪些句子像 AI）；一键「去 AI 味改写」 |
| 强烈建议 | >60 | 珊瑚徽章 + 高危标注；「去 AI 味改写」按钮高亮；文案提示「批量同质化内容是平台治理对象」 |

- **去 AI 味改写规则**：保留信息结构与事实要点，改写方向 = 口语化（加语气词/短句/断句）+ 个人化（按用户人设插入第一人称视角）+ 节奏不均质化（长短句交错）；改写后**自动复检一次**并展示新评分；用户可对比原稿/改写稿。
- **边界**：评分是参考信号不是平台判定结果的预测——页面固定文案「AI 味评分帮助降低同质化风险，不代表平台审核结论」；改写不改变内容安全检测流程（FR-11 照常）。
- **计费**：交付自动检测免费；手动检测与改写计入成本账本（FR-08）。

### FR-19 对话式 Agent（服务号对话框） `P1`（v1.3 新增）

> **定位**：移动端最短输入路径——「微信里转发链接，爆款就拆好了」。竞品全是工具网站形态（打开网站→登录→粘贴），无人做自有载体的原生对话式拆解。复用 ClawBot v1.4.0 已验证的 15 条指令意图识别逻辑，资产平移零浪费。

- **触发**：用户在**认证服务号**对话框发送消息。
- **L1 快捷指令**（P1 首发版）：

| 用户发送 | 系统识别 | 响应（客服消息卡片） |
|---|---|---|
| 粘贴链接（xhs / bilibili / youtube / douyin） | 平台自动识别（复用 FR-14 路由） | 「已开始拆解《标题》· 预计 3 分钟 · 完成后通知你」+ 额度校验（FR-10） |
| 「选题」 | 意图：今日雷达 | 今日 Top 3 选题摘要卡（标题+综合分+一句仿写角度）+「回复 1/2/3 直接写」 |
| 回复数字 N | 意图：确认生产 | 「已入队 · 任务号 XXX」+ 完成通知 |
| 「效果」 | 意图：数据日报 | 昨日增量卡（赞/藏/评三数 + 最佳笔记） |
| 「翻红」 | 意图：翻红入口 | 「发现 N 篇潜力股」+ 首篇诊断摘要 + 引导 H5 查看完整报告（FR-17） |
| 「成本」 | 意图：成本查询 | 近 7 天用量与金额摘要（付费用户） |
| 「帮助」 | 意图：指令表 | L1 指令菜单卡 |

- **L2 追问打磨**（P1 后半）：成品卡片发送后，用户在 48h 窗口内回复自然语言指令——「换个开头」「更口语化一点」「第二段展开」→ 系统按指令局部重写并回发新版本；连续追问共享同一任务上下文。
- **回复通道规则**：
  1. 用户主动发消息后 **48h 内**用客服消息接口即时回复 `[TBD：接口条数上限按微信最新文档验证]`。
  2. 超出 48h 窗口的事件类通知（任务完成/日报/翻红结论）统一走**模板消息**（点开直达 H5 对应页）。
  3. 客服消息发送失败 → 降级模板消息 → 最终站内待读（与 §2.3 触达降级链一致）。
- **边界**：
  1. 复杂操作（定位设置、看板浏览、模板管理、账号注销）一律回复引导卡片「这个去网页操作更顺手」+ 直达链接——对话框只做**高频轻交互**，规避窗口限制与富交互短板。
  2. 微信内 H5 **不做收款**（公众号 H5 在 iOS 端同样受虚拟支付约束）——额度引导卡片链接到官网收款页（系统浏览器打开）。
  3. 视频成品不在对话内直接发送（微信内置浏览器下载体验差）→ 回复摘要卡 +「在浏览器打开下载」引导。
  4. 无法识别的消息 → 兜底回复指令菜单（不做自由聊天，避免不可控对话内容）。
- **鉴权**：服务号 openid 与 Web 账号体系打通（微信网页授权，§2.1）；对话指令的操作权限与数据边界同 H5（uid 硬隔离）。
- **与 ClawBot 的关系**：ClawBot 的指令意图识别与任务链路逻辑**平移复用**；ClawBot 本体保留为种子用户实验通道（不承诺 SLA）；企微群 Bot 版本（代运营团队 @机器人 协作）列 P2。

## 6 界面设计

> 视觉线框沿用 v1.0 HTML 附录（docs/prd/小红书仿写助手-小程序版PRD-v1.0.html §6.3）：首页选题 / 定位引导 / 生产交付 / 数据看板 / 我的 五屏。本节为其文字化规格 + 语义规则。**v1.3 形态改判说明（R19）**：线框按移动端布局绘制，语义全部映射到响应式 Web——移动端布局照常适用；桌面端为同一信息架构的宽屏布局（数据看板/长文案编辑在桌面增强）；原小程序特有能力替换为 Web 等价物（wx.loadFontFace → WebFont 自托管加载；保存到相册 → 长按保存/下载；订阅消息 → 服务号模板消息）。

### 6.1 设计调性：「旅行编辑部」

用户是旅行自媒体人，产品要给的感受是——**「有一位专业编辑每天为我的账号挑选题、写稿、盯数据」**，而不是一个冷冰冰的 SaaS 工具。整体采用杂志编辑部风格：暖纸底色、衬线刊头、车票式标签、纸质卡片；克制、专业、有人味。拒绝科技感渐变紫与后台仪表盘味。

### 6.2 设计 Tokens

| Token | 规范 |
|---|---|
| **色彩** | 米纸白 `#FAF6EF`（底）· 落日珊瑚 `#E8553F`（主色/CTA）· 松林墨绿 `#1F3D2B`（数据/成功）· 沙金 `#D9A441`（热度/预警）· 墨色 `#2B2620`（正文）· 纸边 `#E5DCCB`（描边） |
| **对比度** | 小号正文/辅助文字用深珊瑚 `#C93E2A`（浅色小字对比度达标）；白字仅用于大号加粗或实心按钮 |
| **字体** | 标题/数字：思源宋体（Noto Serif SC）——杂志刊头感；正文：苹方/思源黑体。**落地方式**（v1.3 Web 化）：WebFont 自托管 + 标题子集化（仅标题字符集），降级栈 苹方 → 系统黑体；宋体仅作渐进增强 |
| **卡片** | 纸片隐喻：米白卡面 + 1px 纸边描边 + 2px 偏移硬影（非模糊大阴影），圆角 12px |
| **标签** | 行李签/车票式胶囊标签（赛道、探索模式、热度）；评分用水平条 |
| **动效** | 轻盈有「翻页」感：清单卡片 stagger 入场（50ms 间隔）、按钮按压 0.97、进度点亮带弹性、交付完成轻触感反馈；不做常驻循环动画 |
| **深色模式** | V1 锁定浅色（纸感主题不做半深半浅）；深色变体列入远期 |
| **字号** | 正文 ≥12px、注释 ≥10px、tab 标签 ≥10px；v1.0 线框中的小字号仅为示意 |

### 6.3 信息架构

底部四 Tab：**选题（首页）/ 生产 / 数据 / 我的**。核心旅程「选题 → 生产 → 数据」各占一 Tab，符合每日使用节奏：早看选题、午管生产、晚看数据。

- 例外：**定位向导页隐藏 tabbar**（FR-02）。
- 平台习惯：胶囊按钮左侧避让；列表下拉刷新；发布记录解绑用**左滑操作**（替代按钮，符合微信习惯）。

### 6.4 组件语义规则（v1.1 新增，强约束）

| 规则 | 定义 |
|---|---|
| **评分条颜色映射** | ≥9.0 松林墨绿 · 8.0–8.9 沙金 · <8.0 纸灰 `#C9BFA8`——颜色只由分值决定，与维度无关 |
| **CTA 主次** | 综合推荐分最高的 1 张卡 =「今日首推」：实心珊瑚 CTA + 首推徽章；其余卡片一律描边 CTA |

## 7 共享规则

### 7.1 通知策略（跨模块统一，v1.3 通道改判）

| 事件 | 通道与时机 | 降级 |
|---|---|---|
| 选题就绪 | 服务号模板消息，每日雷达完成后（默认 8:00 档） | 首页红点待读 |
| 任务完成 / 失败 | 服务号模板消息，状态变更即时 | 生产 Tab 常驻 + 待读 |
| 数据日报 | 服务号模板消息，每日回采后（默认 9:00 档）；**仅当日有增量才推** | 数据页查看 |
| 翻红观察结论（v1.3） | 服务号模板消息，观察期满即时 | 数据页翻红报告 |
| 交付 48h 未登记 | 提醒通知 1 次 `[TBD：频次以防打扰为准]` | 生产 Tab 置顶提醒条 |
| 关注引导 | 仅价值交换节点展示，单日单用户 ≤1 次 | 静默跳过（降级站内待读） |

未关注服务号用户：全部事件降级站内待读（红点 + 角标），信息不丢；任何通道失败最终落到站内待读。

### 7.2 数据口径（与 Bot 版一致，一处定义）

- **清单归属**：有定位用户读个人专属清单（按其关键词+人设独立评分）；无定位用户读全局清单。个人清单按日覆盖。
- **回采窗口**：仅自动回采近 30 天发布的笔记；超窗笔记保留历史数据，可手动刷新。
- **成本归属**：生产记任务号、雷达记日期、回采记回采批次；单篇成本 = 该任务号全部条目聚合。
- **同端互斥**：同一 uid 同时只用一个活跃通道推送，避免双端重复打扰。
- **来源平台口径**（v1.2 新增）：任务记录来源平台（xhs / bilibili / youtube / douyin / upload）；选题清单仍仅小红书（多平台雷达为 P2）；发布登记与效果回采口径不变（仅小红书链接可登记回采，FR-06）。
- **回采数据用途扩展**（v1.3 新增）：同一份回采时间序列服务三个消费者——① FR-06 效果看板（人读）② FR-17 翻红识别（算法读：S1/S2 信号与诊断信号）③ FR-16 模板反写（P2，算法读：模板效果标注）。一处采集、多处消费，不重复抓取。
- **潜力股判定口径**（v1.3 新增，FR-17）：S1 分位 = 发布 72h 内赞藏评总量在该用户全部笔记中的排名分位（账号内相对值）；S2 停滞 = 近 7 天赞藏评增量合计 < 2。判定每日回采后批量重算一次。
- **红狐互动数口径**（v1.3 新增，R22）：红狐 search API 返回的互动数（赞/藏/评/转）为**入库快照**，非实时值——探索卡片（FR-03）展示时标注「数据为入库快照」；效果看板（FR-06）的增量与趋势**仅以自建回采时间序列为准**，不混用快照值。

### 7.3 权限

| 操作 | 规则 |
|---|---|
| 查看/生产/登记 | 仅本人数据；uid 边界硬隔离（清单、任务、发布记录、成本、额度均按 uid 过滤） |
| 定位修改 | 本人可改，改后次日清单生效，当日的可手动重抓 |
| 发布记录解绑 | 左滑操作 + 二次确认；解绑后该笔记停止回采 |
| 账号注销 | 二次确认 + 数据范围说明（FR-11）；注销后 openid 解绑，额度与任务数据清除 |

### 7.4 额度与计费规则（v1.1 新增，一处定义）

- **额度维度**：每日选题查看条数、每日生产次数；免费档数值 `[TBD：随定价评审]`。
- **扣额时机**：生产在服务端入队成功时扣额；选题按实际下发条数计。
- **返还规则**：生产失败自动返还；同一任务重试不重复扣额。
- **重置**：每日 0 点（北京时间）。
- **闸门**：服务端校验为准，前端展示仅作引导；绕过前端的请求一律以服务端校验结果执行。
- **付费**：升级后额度提升或解除 `[TBD：档位与定价]`；FR-03 / FR-04 / FR-08 / FR-10 引用本节，不各自定义。

## 附录 B：决策依据沉淀（v1.3 新增）

> 本附录沉淀 v1.2 → v1.3 期间全部产品决策的背景、论证过程与结论，供后续追溯「为什么这么定」。数据时点：2026-10；市场规模类数据会随时间变动，重大决策前需复核。

### B.1 平台政策环境（合规生死线检查）

小红书 2026.3–2026.5 密集出台 AI 治理政策，边界已清晰，是本产品所有内容功能设计的政策底座：

| 平台态度 | 具体内容 | 本产品对位 |
|---|---|---|
| **鼓励**：AI 作为「创意放大器」 | 知识可视化、虚拟角色、视觉创作；判断标准是「是否保留真实性与原创价值」，而非「是否用了 AI」（2026.5 AI 治理开放日） | 拆解结构 → 原创仿写 → 人工过稿 → 用户自主发布——完全落在鼓励侧 |
| **反对**：AI 托管运营 | 自动生成+自动发布+模拟互动；截至 2026.5 处置 120 万+ AI 托管账号、18 万篇 AI 造假笔记 | 明确不做自动发布与评论互动（§3.3）；发布动作 100% 归用户 |
| **反对**：批量同质化低质内容 | AI 批量生产同质化笔记 | 仿写坚持「一稿一拆一改」；FR-18 AI 味检测把「不被识别为批量内容」产品化 |

**政策结论**：小红书画的线是「人用 AI」vs「AI 装人」——本产品的「人工过稿」哲学与平台政策同向，应作为品牌资产经营而非包袱。风险执行尺度变化列为持续观察项。

### B.2 形态改判：小程序 → 响应式 Web（R19）

**改判路径**：v1.2 维持小程序（R16）→ 收款通道分析发现官网收款可绕开小程序支付约束 → 竞品调研发现 6 家中 5 家纯网页、收款全在官网 → 「手机发布是否牺牲体验」专项分析 → 改判。

**核心论证**：

1. **「手机发布」与产品形态无关**：用户在小红书 App 发布，不经由本产品——本产品只负责「取走产物」（复制文案/存图卡），该动作用响应式 H5 完全覆盖。
2. **付费主力工作场景在桌面**：腰部博主/高频创作者/代运营的长文案编辑、数据看板、批量任务管理在桌面端体验碾压手机；创作者工作流实证（「在电脑上完成所有能完成的工作，把手机变成最后一道关口」）。
3. **收款合规**：小程序虚拟商品必须接虚拟支付（iOS 走 Apple IAP 抽成 30%），独立官网收款不受此约束——竞品形态实证了这条路径。
4. **服务号三合一补齐微信生态能力**：入口（菜单/模板消息）+ 触达（模板消息，对沉默用户覆盖强于小程序订阅消息）+ 登录（网页授权静默，追平小程序体验）。
5. **代价与对冲**：牺牲「即点即用」级丝滑度与订阅消息精细度——小程序降为 P2 观察项而非取消，后端 REST 前端无关，数据异常（移动端占比/流失）随时回补，沉没成本 ≈ 0。

**载体架构**：一套响应式代码，三入口（微信内打开 / 手机浏览器 / 桌面浏览器）；服务号是对话式 Agent（FR-19）与触达（FR-07）的合规载体。

### B.3 竞品分析与市场可行性（R20 功能组合的依据）

**调研范围**（2026-10，10 家）：生成类 6 家（红墨 RedInk、红薯通AI、XHSPlus、Reditor、拾稿集、VantaSell）+ 拆解仿写类 4 家（AnyToCopy、小加同学 JustAI、Beav、拾意）。

**市场底数**：小红书月活 4 亿+ / 日活 1.7 亿+（2026.5）；日均笔记 900 万篇（供给竞争白热化）；生成式 AI 用户 6 亿、AIGC 市场 2026 预测 1500 亿级——「用 AI 提升内容产能」需求大盘真实。

**竞品矩阵核心发现**：

1. **效果回采闭环 = 全市场空白**：10 家竞品全部止步于「生成交付」，无一具备发布登记→赞藏评回采→数据反哺能力——而这是代运营客群的付费核心理由。
2. **视频成片能力稀缺**：仅本产品规划完整 TTS+图卡合成链路。
3. **直接竞品路线图重合**：拾意的「多平台→ASR→拆解→仿写」与本产品 FR-14 高度重合——验证方向，也意味着窗口期竞争。
4. **「一键复刻」类功能踩搬运红线**（小加同学）：合规姿态本身是竞争差异。

**替代威胁评估**：豆包 3.82 亿 MAU 的免费通用能力是最大变量（Kimi 月活回落至 700 万的前车之鉴：纯靠模型能力的 C 端产品守不住）；防御物 = 工作流整合（雷达自动推送 vs 手动收集）+ 数据资产（回采历史、模板库）+ 成片链路——**卖流水线，不卖模型**。

**红狐官方 skill 审读补充（R22，2026-10-17）**：审读 redfox-community 仓库的 fetch_xhs_hot_articles.py（Coze 平台 skill）——印证三件事：① search API 能力面比本产品假设的更宽（relatedSearches/hotTopics/cover/latestHotArticles 均未利用，已吸收进 FR-03/FR-16）；② 红狐官方以「智能体挂载数据能力」为推广场景，与 FR-19 对话式 Agent 路线同向；③ 其互动数为入库快照——第三方生态拿不到时间序列，**回采闭环的独占性得到反证**。

**可行性结论**：有条件可行——赛道已验证（10 家共存 + 红墨 8w 付费创作者）、差异化真实存在（数据闭环）、政策可管理（形态在鼓励侧）；成立前提 = 三条战略纪律（B.4）。止损信号（诚实清单）：上线 3 个月代运营客群付费转化 <3% 且通用生成被大厂功能碾压 → 退守「个人效率工具+低价走量」或及时止损。

**功能发散与收敛过程**：第一轮发散（A/B 实验/语气指纹/对标追踪等）评审后判定为「链路增强、未开新维度」；第二轮打开博主时间预算三块（写新的/管旧的/变成钱），收敛出三层产品叙事——**「不只帮你写下一篇，还帮你救活上一批，并把规律存下来越用越准」**：

| 层 | 功能 | 竞争位置 |
|---|---|---|
| 增量生产 | 双链路核心（雷达选题/链接拆解 → 仿写 → 成片） | 红海，必需，竞品都在 |
| 存量优化 | FR-17 翻红计划 | **无人区**（回采独占） |
| 规律沉淀 | FR-16 规律引擎 + FR-18 AI 味检测 | **无人区 + 数据飞轮**（越用越准） |
| 入口体验 | FR-19 对话式 Agent | 无人做自有载体对话式拆解 |

### B.4 战略纪律（R21，全团队对齐）

1. **不打通用生成市场**——所有资源聚焦「拆解→仿写→成片→发布→回采」闭环客群（腰部博主 + 高频创作者 + 代运营），不与生成类工具拼通用市场。
2. **把「人工过稿」做成品牌资产**——对齐平台「人用 AI」政策导向，与「一键复刻/批量搬运」类竞品形成合规区隔；AI 味检测（FR-18）是其产品化表达。
3. **尽快建立数据飞轮**——回采历史、质检基线、模板-效果关联是唯一随时间增值的壁垒，模型能力不是；数据闭环三功能（FR-16/17/18）全部服务于这条纪律。

### B.5 用户分层依据（R18）

v1.2 原定义「自媒体小白（旅行赛道）」是冷启动种子用户的历史事实，与演进的定价（¥49–199/月）和功能（多平台拆解、数据回采）错位——小白付费能力最弱。按「痛点匹配 × 付费能力 × 获客可达」五层重构：

| 层 | 画像 | 档位 | 决策 |
|---|---|---|---|
| L1 素人新手 | 起号期，粉丝 <1千 | 免费 + ¥0.99 | **漏斗层**：口碑源与转化种子 |
| L2 腰部个人博主 | 粉丝 1千–5万，周更 1–3 篇 | ¥49 | **营收主力**（竞品已验证付费意愿） |
| L3 高频创作者 | 日更/准日更，账号即副业 | ¥99 | **营收主力**：视频档目标人群 |
| L4 代运营主理人 | 服务 3–10 客户号 | ¥199+ | **差异化王牌**：FR-12 周报海报 + FR-06/17 效果证明即为此设计 |
| L5 企业新媒体 | 品牌官方号 | — | **明确不做**（B2B 销售周期不匹配） |

**赛道策略**：全赛道开放（关键词订阅机制天然按用户自定义赛道运作）——不设类目限制，运营侧不预设赛道偏好；种子用户的旅行赛道仅作为冷启动测试场景，不写入产品约束。
