# 小红书内容自动化 Agent 设计文档（选题雷达 + 仿写生产线）

- 版本：v1.1（新增第 3 章「触发层与多用户接入」，原第 3-10 章顺延为第 4-11 章）
- 日期：2026-09-17（v1.1 更新于 2026-09-19）
- 状态：设计定稿，POC 进行中
- 项目：video_generate

## 1. 概述

### 1.1 目标

输入小红书对标笔记，自动完成：**选题发现 → 笔记获取 → 拆解仿写 → 图文笔记生成 → 视频笔记合成**，产出可直接人工发布的图文 + 视频内容。

账号定位：**提供旅游行程规划与定制服务的旅行家**（服务导向型旅游垂类账号）。

### 1.2 边界（本期不做）

- 不做自动发布（账号风控风险，人工发布）
- 不做批量矩阵（POC 单篇验证，规模化属 Phase 2）
- 不复用对标笔记原图（版权 / 搬运判定风险）

## 2. 系统架构

```
[配置] 账号定位 · 关键词体系 · 人设
   ↓
① 选题雷达（每日定时）
   关键词采集(数据 API) → LLM 选题评分 → 选题清单
   ↓ 人工确认选题（可切全自动）
② 仿写生产线（单篇自动）
   对标详情获取 → 拆解仿写(人设注入) → 图文生成 → 视频合成
   ↓
交付：图文笔记包 + MP4（人工发布）
```

两阶段解耦：雷达产出结构化选题清单，生产线只消费清单中确认的条目，互不依赖实现细节。

触发与交互层独立于两阶段之外（第 3 章）：飞书 / 微信等渠道经 TriggerAdapter 统一接入，推（雷达定时推送清单）与拉（用户对话指令）双模式汇入同一流水线，内核对渠道无感知。

## 3. 触发层与多用户接入（TriggerAdapter）

> v1.1 新增。借鉴 MyAgent/Transformer 的「bot 触发层与 pipeline 内核解耦」模式：渠道怎么接、用户怎么进，与生产内核完全隔离。

### 3.1 设计动机与原则

- **内核无感知**：雷达/仿写/图文/视频流水线不 import 任何渠道 SDK，新增渠道只需实现一个 Adapter
- **推拉统一**：雷达定时推送（推）与用户对话指令（拉）汇入同一任务队列，下游不区分来源
- **多用户就绪**：会话、配置、产出、配额按用户隔离，为 Phase 2 商业化计费预留
- **渠道能力降级**：富交互渠道（卡片/按钮）与纯文本渠道（序号回复）共用同一套指令协议

### 3.2 总体结构

```
[渠道] 飞书(open_id) / 微信(wx_id)
   ↓ TriggerAdapter.on_message → 统一 Intent
[路由] Router：用户路由 · 意图解析 · 确认卡点
   ·  会话状态（SQLite，按 uid 隔离）
   ·  用户配置（profile per user）
   ·  配额计费（Phase 2）
   ↓ 已确认任务（推/拉两路在此汇合）
[内核] Pipeline：雷达选题 / 手动对标 → 拆解仿写 → 图文 → 视频
   ↓
[交付] Deliver：按渠道 capabilities 降级交付（卡片 → 图片/视频直发 → 文件/链接兜底）
```

### 3.3 TriggerAdapter 接口定义

`bot/base.py` 抽象基类；渠道适配器只需实现以下成员，Router 与内核只依赖抽象：

```python
class TriggerAdapter(ABC):
    name: str                            # "feishu" | "weixin"

    def start(self): ...                 # 启动监听（长连接 / 网关回调）
    def on_message(self, raw) -> Intent  # 渠道原生消息 → 统一 Intent
    def send_text(self, uid, text): ...
    def send_image(self, uid, path): ...
    def send_video(self, uid, path): ...
    def send_file(self, uid, path): ...  # 兜底（视频超限等场景）
    def capabilities(self) -> set[str]   # 渠道能力声明，如 {"card", "video"}
```

统一 Intent Schema（渠道差异在 Adapter 内抹平）：

```json
{ "user_id": "feishu:ou_xxx", "text": "仿写第 2 条", "media": [], "ts": 1789000000 }
```

### 3.4 推 / 拉双模式

| 模式 | 入口 | 流程 |
|---|---|---|
| 推（雷达主导） | cron 每日定时 | 雷达评分 → Adapter 推送当日选题清单 → 用户回复序号确认 → 进入生产线 |
| 拉（用户主导） | 对话窗口 | 用户发指令，或粘贴对标笔记链接 / JSON / 转发图片 → Router 解析意图 → 进入生产线 |

两路汇合同一「已确认任务」队列；确认卡点保留人工环节（选题确认 + 终审发布），与 1.2 边界一致。

### 3.5 指令集（v1）

| 指令（示例写法，非精确匹配） | 动作 |
|---|---|
| /选题、今天有什么选题 | 推送当日选题清单 Top 5（含评分与推荐角度） |
| 仿写第 2 条、确认 2 | 确认选题，触发生产线 |
| 粘贴笔记链接 / JSON / 转发图片 | 手动输入对标（绕过雷达，走第 5 章输入层） |
| /状态 | 查询生产进度（拆解中 / 出图中 / 合成中 / 已交付） |
| /换角度 2 强调预算 | 重新生成该条的 rewrite_angle 后再确认 |
| /help | 指令帮助 |

指令解析：先精确 / 正则匹配，未命中转 LLM 意图解析兜底（同 Transformer 的 router 模式）。

### 3.6 多用户路由与隔离

- 唯一标识：`{channel}:{open_id}`（飞书 `ou_xxx` / 微信 `wx_id`）
- 隔离维度：会话状态、人设与关键词配置（每用户一份 profile）、产出目录 `workspace/users/{uid}/`、配额与计费（Phase 2）
- Phase 1 白名单制：仅允许配置用户触发。飞书侧配 open_id 白名单；微信侧走 ClawBot 的 DM pairing 配对批准（见对接验证清单）

### 3.7 渠道对照与交付差异

| 维度 | bot_feishu.py | bot_weixin.py |
|---|---|---|
| 协议 | lark-oapi WebSocket（官方） | ClawBot / iLink（hermes gateway 中转，2026.3 开放） |
| 消息能力 | 文本 / 图片 / 文件 / 交互卡片 | 文本 / 图片 / 视频 / 文件 |
| 富交互 | Interactive Card：选题清单卡片 + 按钮确认 | 无卡片：纯文本清单 + 序号回复 |
| 图文交付 | 4 图直发 + 文案转飞书文档（可编辑）+ zip 包 | 4 图逐张直发 + 文案整段文本消息 |
| 视频交付 | 文件直发（API 约 ≤30MB，POC 成片 20MB 可发） | 视频直发（上限待实测；超限转网盘链接） |
| 参考实现 | Transformer bot.py 已验证模式 | 未验证：先跑 [ClawBot 对接验证清单](2026-09-19-clawbot-integration-checklist.md)，通过后再实现 |

### 3.8 目录规划（Phase 1）

```
agent/
  bot/
    base.py          # TriggerAdapter 抽象基类 + Intent Schema
    router.py        # 用户路由 / 意图解析 / 确认卡点
    bot_feishu.py    # 飞书适配器（lark-oapi）
    bot_weixin.py    # 微信适配器（ClawBot / iLink，经验证后实现）
    deliver.py       # 按渠道能力降级的交付器
  pipeline/          # 生产内核（雷达 / 仿写 / 图文 / 视频），渠道无感知
```

## 4. 选题雷达（前置模块）

### 4.1 输入配置

人设与关键词体系集中在 `profile.yaml`，示例见 `poc/radar/profile.yaml`。关键词分三层：

| 层级 | 示例 |
|---|---|
| 人群层 | 带娃游、亲子旅行、带老人出行、情侣出游 |
| 主题层 | 避寒、玩雪、错峰、穷游、citywalk |
| 服务意图层 | 行程规划、定制游、X 天 X 晚、保姆级攻略 |

关键词体系非静态：每周从抓回的爆款笔记中自动发现新热词并回填（Phase 1 实现）。

### 4.2 数据源（2026-09-17 实测定稿）

| 数据源 | 能力 | 价格 | 定位 |
|---|---|---|---|
| **红狐数据 redfox.hk** | 关键词搜笔记（热度排序，自带**全文正文**）、爆款洞察（含相关性评分）、日/周爆款榜、黑马榜（低粉爆款）、评论、热门账号榜、视频提文案 | ¥0.02/次，无月费 | **主源** |
| Apify · SocialDataX | 笔记搜索、热榜、话题、评论、详情、博主作品（数据实时性好） | $4.99/1000 条 + Apify $39/月 | 备源（需高实时性时） |
| 手动粘贴 | 用户已有工具导出的笔记数据 | 免费 | 兜底 |

**红狐实测结论**（对比 SocialDataX）：同笔记交叉验证数据一致（互动数差异 5-8%，快照时间差）；"避寒"关键词精准度显著更高（无游戏噪音）；优质库机制保证爆款浓度；错误处理规范（未收录不扣费）。已知瑕疵：详情接口（优质库）覆盖不全（搜索接口自带全文，无影响）、互动数据有数天缓存滞后。

所有数据源经适配器统一为内部 Schema（见 4.5），可热切换。适配器：`fetch_redfox.py`（主）/ `fetch_apify.py`（备）。

### 4.3 热度计算（数值层，代码完成）

```
加权互动量 E = 点赞 + 收藏×2 + 评论×3 + 分享×2
原始热度 H_raw = log10(E + 1) × 10
时间衰减 D：发布 ≤7 天 ×1.2；≤30 天 ×1.0；≤90 天 ×0.8；更早 ×0.5
热度 H = H_raw × D
```

候选门槛（可配置）：`H ≥ 25 且 点赞 ≥ 500`。不过门槛的笔记不进入语义评分，仅留存观察。

### 4.4 LLM 语义评分（四维，每维 0-10）

```
机会分 = 0.3×赛道相关性 + 0.3×爆款潜力 + 0.2×人设匹配度 + 0.2×服务转化空间
硬门槛：相关性 < 6 或 爆款潜力 < 5 直接淘汰
```

| 维度 | 评什么 |
|---|---|
| 赛道相关性 | 与旅游行程规划定位的契合度（探店/纯风景大片 → 低分） |
| 爆款潜力 | 标题钩子强度、结构可复用性、话题热度（结合数值热度 H） |
| 人设匹配度 | 该选题能否以"规划感"视角重讲（表格化、天数/预算/节奏） |
| 服务转化空间 | 能否自然引出"帮你定制行程"的服务钩子 |

评分 prompt 模板：`poc/radar/prompts/topic_scoring.md`。

## 5. 对标笔记输入层

三种输入方式统一为标准笔记 Schema，下游无感知：

```json
{
  "note_id": "…", "url": "…", "type": "image",
  "title": "…", "content": "…",
  "tags": ["#话题"],
  "likes": 0, "collects": 0, "comments": 0, "shares": 0,
  "images": ["https://sns-img-…"],
  "top_comments": [ { "text": "…", "likes": 0 } ],
  "author": { "nickname": "…", "followers": 0 },
  "published_at": "2026-09-14 23:09:22"
}
```

已实测验证：`sns-img-bd.xhscdn.com` 图片链接可直接下载（1080×1440 JPEG，无登录态、无防盗链），多模态视觉分析可行。

字段覆盖度：选题 / 标题钩子 / 正文结构 / 话题标签 / 视觉风格（图片下载）/ 互动数据 / 人设信息全覆盖；热门评论文本为可选增强（数据源支持时自动补全）。

## 6. 拆解仿写

### 6.1 五层拆解框架

1. 选题层：赛道、痛点、目标人群、情绪价值
2. 标题层：钩子类型（数字 / 悬念 / 反差 / 痛点）、关键词、emoji 用法
3. 正文层：结构骨架（钩子开头 → 痛点共鸣 → 干货主体 → 互动引导）、段落节奏、口吻
4. 视觉层：封面文字布局、色调、图片风格（多模态分析对标图片）
5. 数据层：赞藏评比例判断内容类型（收藏高 = 干货型，点赞高 = 情绪型），评论区共鸣点

### 6.2 同构异题策略

保留：结构公式、钩子模式、排版节奏、话题标签策略。
替换：主题细节、案例、数据、口吻细节。

### 6.3 人设注入（旅行家定位专属）

- 内容强化"规划感"：天数 / 预算 / 节奏表格化，对标讲"去哪"，仿写强化"怎么排"
- 结尾固定服务钩子："评论区留言人数/天数/预算，帮你出定制行程"
- 口吻：专业但不端着，像懂行的朋友给建议

### 6.4 原创度自检

产出后与原文计算 n-gram / embedding 相似度，超过 0.6 自动重写；两轮仍超标则转人工。不复用对标原图。

## 7. 图文笔记生成

- 配图脚本与仿写文案同步产出，每张图有明确信息职责（封面抓眼球 → 内页承接痛点 → 干货主体 → 尾页 CTA）
- 封面：AI 生图（Seedream）出无字底图 → HTML/CSS 渲染大字标题 → 截图合成。**文字不直接 AI 生成**（规避中文渲染错误）
- 内页：展示类以 AI 生图为主；干货类以 HTML 模板排版为主 + AI 插图
- 规格：3:4 竖版（1242×1656）

## 8. 视频笔记合成

- 口播文案改写（去书面化）→ 分镜脚本（30-45s ≈ 5-7 镜头 × 5-10s）
- Seedance 逐镜头生成；**首帧锚定**：用生成的封面 / 内页图作 image-to-video 首帧，保证风格一致
- TTS 旁白配音（VO，规避口型问题）→ 时间轴字幕（ASS）→ BGM → ffmpeg 合成（转场 + ducking 混音）

## 9. 成本估算

| 项目 | 估算 |
|---|---|
| 雷达（每日 10-20 词 × 20-50 条） | 约 2-10 元/天 + LLM 评分 < 1 元 |
| 生产单篇（图文 + 30-45s AI 视频） | 约 15-50 元（视频为大头） |
| 日更 1 篇全链路 | 约 600-1800 元/月 |

## 10. 风险与对策

| 风险 | 概率 | 影响 | 对策 |
|---|---|---|---|
| 数据 API 失效 | 中 | 中 | 三源适配器热切换；手动格式兜底 |
| 批量 AI 内容被平台限流 | 中 | 高 | 人工终审、发布节奏控制、每篇差异化角度 |
| 仿写被判搬运 | 中 | 高 | 相似度自检 + 同构异题 + 不复用原图 |
| 视频镜头风格漂移 | 高 | 中 | 首帧锚定 + 统一风格 prompt |
| 中文生图文字出错 | 高 | 低 | 文字全部走 HTML 排版层 |
| 全自动选题漂移 | 中 | 中 | POC 强制人工确认选题，稳定后逐步放开 |
| 微信 ClawBot 通道不稳（2026.3 新开放） | 中 | 中 | 双渠道适配器互为备份，飞书先行；ClawBot 上线前压测一周（见 [ClawBot 对接验证清单](2026-09-19-clawbot-integration-checklist.md)） |

合规：浏览器/API 抓取控制在低频；AI 生成内容发布时按平台要求标注。

## 11. 实施路线图

- **Phase 0 · POC（当前）**：雷达单次运行（抓取 + 评分 + 选题清单）→ 仿写质量评审 → 封面 / 内页验证 → 单镜头视频验证 → 全片合成。产出 1 篇图文 + 1 条视频 + 各环节质量结论
- **Phase 1 · 固化**：Python pipeline 模块化；触发层接入（bot_feishu 先行，ClawBot 验证通过后并列）；定时调度，人工仅终审
- **Phase 2 · 规模化（可选）**：关键词自动扩展、发布端对接、数据回流闭环（仿写笔记互动数据回流优化评分与 prompt）
