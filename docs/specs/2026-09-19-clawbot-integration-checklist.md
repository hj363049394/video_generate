# ClawBot 对接验证手册（微信渠道 · bot_weixin.py 前置验证）

- 版本：v3.0 · 日期：2026-09-19（v3.0：聚焦「你要验证什么 + 逐项流程」；沙箱源码预验证结论移至附录 A）
- 执行环境：你的本地电脑（Windows + WSL2 Ubuntu）。扫码需真人 + 手机微信，服务端阈值需真实登录通道，长期稳定性需本地常驻——这三类沙箱无法代做，故有本手册
- 总规则：**任何一步的实际输出与「预期」不符，就把终端报错 / 微信截图贴回来**，由我判断是环境问题还是通道问题

## V1 · 安装与扫码登录（一切的前提）

**目的**：装好 hermes 网关并完成微信授权，让 bot 在你的微信里活着。

### 准备清单

- Windows 电脑（可重启一次）
- 手机微信（扫码用）
- 一个 LLM API Key（bot 回复消息的大脑；国内推荐智谱：[open.bigmodel.cn](https://open.bigmodel.cn/) 注册 → 控制台创建 API Key，复制备用）

### 步骤

**1.1 确认 WSL2**

PowerShell（管理员）执行：

```powershell
wsl --list --verbose
```

- 已有 Ubuntu 且 VERSION 是 2 → 跳到 1.2
- 没有 → 执行 `wsl --install`，完成后**重启电脑**，首次进入 Ubuntu 设置用户名密码

**1.2 进入 Ubuntu，检查 Python**

开始菜单打开「Ubuntu」（或 PowerShell 输入 `wsl`），执行：

```bash
python3 --version
```

预期：`Python 3.11.x` 或更高。低于 3.11 → 贴出版本号给我。

**1.3 安装 uv**

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
source ~/.bashrc
which uv
```

预期：`which uv` 输出一个路径（如 `/home/xxx/.local/bin/uv`）。

**1.4 克隆 hermes-agent**

```bash
cd ~
git clone --depth 1 https://github.com/NousResearch/hermes-agent.git
```

预期：几秒到几十秒完成（必须带 `--depth 1`，完整克隆 >80MB 国内极慢）。卡住超过 2 分钟 → Ctrl+C 后重试一次，仍失败贴报错。

**1.5 安装依赖**

```bash
cd ~/hermes-agent
uv venv venv && source venv/bin/activate
uv pip install -e ".[messaging,cron,cli,pty,mcp,dev]" \
  -i https://pypi.tuna.tsinghua.edu.cn/simple/ \
  --trusted-host pypi.tuna.tsinghua.edu.cn
```

预期：正常跑完。**注意**：必须用清华源（命令已带）；不要换成阿里源（版本不全会报 `No solution found`）。

**1.6 体检**

```bash
hermes doctor
```

预期：无红色 ERROR 行。有红字 → 原样贴回来。

**1.7 配置模型**

```bash
hermes model
```

在交互列表中选择智谱 GLM（或你已有的其他提供商），按提示粘贴 API Key。完成后可再跑一次 `hermes model` 确认当前模型已设置。

**1.8 网关配置 + 扫码**

```bash
hermes gateway setup
```

按顺序遇到这些提示，这样选：

| 提示 | 你的选择 |
|---|---|
| 平台选择列表 | 方向键选 **Weixin/WeChat（微信）**，回车 |
| `Start QR Login now? [Y/n]` | 输入 **Y** 回车 |
| （终端出现二维码/二维码链接） | 复制链接到浏览器打开 → 手机微信「扫一扫」扫描 → 手机上点确认 |
| 私聊消息权限（4 选 1） | 选 **Use DM pairing approval**（配对批准） |
| 群聊权限 | 选 **Disable group chats** |
| `Use your Weixin user ID as the home channel? [Y/n]` | **Y** |
| `Install the gateway as a systemd service? [Y/n]` | **Y** |
| 运行方式（3 选 1） | **User service**（无需 sudo） |

扫码成功后终端会提示登录成功、账号 ID/Token 已保存。

**1.9 完成本人配对**

1. 手机微信打开机器人窗口（扫码确认后微信里会出现），发送任意消息，如「你好」
2. bot 会回复一条**一键配对命令**（一串终端命令文本）
3. 复制这条命令，回到 Ubuntu 终端粘贴执行
4. 终端提示**对接成功**即完成

**1.10 验证**

```bash
hermes gateway status
```

再从微信给机器人发一句「你好」。

### V1 通过判定（3 条全满足）

- [ ] `hermes gateway status` 显示 Weixin 已连接（connected）
- [ ] 微信发「你好」，bot 在数十秒内回复（内容是 LLM 生成的正常回复）
- [ ] `~/.hermes/.env` 文件存在且非空（`cat ~/.hermes/.env | head -3` 能看到内容，不要把内容发出来）

### 常见失败

| 现象 | 处理 |
|---|---|
| 二维码过期 | 终端会自动刷新（最多 3 次）；都过期了就 Ctrl+C 重跑 `hermes gateway setup` |
| 扫码后一直等待 | 检查手机微信是否点了「确认登录」 |
| bot 不回复但 gateway 已连接 | 多半是模型没配好：重跑 `hermes model`，再发消息试 |

## V2 · 基础收发链路

**目的**：确认文本/图片双向正常（源码已确认客户端能力，这里是快速实测）。

### 步骤

**2.1 文本 + 长文案**

在微信里给 bot 发一段 200 字左右的文字（随便找一段笔记文案，或让 bot 自己生成一段再复制发回）。

判定：bot 收到的处理正常（能复述/回答内容），回复没有乱码。

**2.2 图片**

给 bot 发 1 张竖版图片（手机截图或相册任选，最好是 3:4 竖图）。

判定：bot 能「看到」图片内容（问它「这张图里有什么」，能正确描述）。**灰图/看不懂 → 失败，截图记录。**

**2.3 bot 发长文本给你**

对 bot 说：「用 200 字介绍一下你自己」。

判定：回复完整送达；若超过 2000 字会被自动分片成多条，属正常。

### V2 通过判定

- [ ] 文本双向正常
- [ ] 图片 bot 可识别、不灰图
- [ ] bot 的长回复完整不截断

## V3 · 视频直发 20MB（关键项：我们的交付方向）

**目的**：验证 **bot → 你**方向能直发 20MB 视频（POC 成片就是 20MB，这是交付链路的核心能力）。

### 步骤

**3.1 准备视频文件（二选一）**

- 方式 A：从 POC 预览页下载 video_001.mp4（浏览器打开 preview.html → 视频播放器右下角下载/另存为）
- 方式 B：WSL 里用 ffmpeg 生成一个 20MB 测试视频：

```bash
sudo apt install -y ffmpeg   # 若未安装
ffmpeg -y -f lavfi -i testsrc2=size=1080x1440:rate=30 -f lavfi -i sine=frequency=440 -t 45 -b:v 3400k -b:a 128k ~/test_20mb.mp4
```

**3.2 让 bot 把视频发给你**

查你的用户名：`whoami`（假设输出 `tom`）。

在微信里对 bot 说：

> 请把 /home/tom/test_20mb.mp4 这个文件发送给我

（把 tom 换成你的实际用户名；方式 A 下载的文件也要先放进 WSL，如 `/mnt/c/Users/你的Windows用户名/Downloads/video_001.mp4`，路径照此写。）

### V3 通过判定

- [ ] 微信里收到**视频消息**（可直接播放），不是打不开的文件
- [ ] 大小无明显缩水（微信里看视频属性或转发到文件传输助手对比）

失败记录：如果 bot 答非所问不会发文件 → 把对话截图发我（这属于 agent 工具链问题，有备选方案）；如果发送报错 → 把终端日志（见 V8 的日志命令）发我。

## V4 · 视频大小阈值（决定「超限转网盘」的阈值）

**目的**：测出 iLink 服务端拒绝大视频的临界点。客户端无限制（源码确认），真实阈值只有服务端知道。

### 步骤

**4.1 生成 50MB 和 100MB 测试视频**

```bash
ffmpeg -y -f lavfi -i testsrc2=size=1080x1440:rate=30 -f lavfi -i sine=frequency=440 -t 120 -b:v 3400k -b:a 128k ~/test_50mb.mp4
ffmpeg -y -f lavfi -i testsrc2=size=1080x1440:rate=30 -f lavfi -i sine=frequency=440 -t 240 -b:v 3400k -b:a 128k ~/test_100mb.mp4
```

**4.2 依次让 bot 发送**

对 bot 说：「请把 /home/tom/test_50mb.mp4 发给我」，成功后再说「请把 /home/tom/test_100mb.mp4 发给我」。

### V4 结果记录

| 测试 | 结果（成功收到 / 报错） | 报错内容（终端日志） |
|---|---|---|
| 50MB | ☐ 成功 ☐ 失败 | |
| 100MB | ☐ 成功 ☐ 失败 | |

任一失败：把终端报错贴回来（日志命令见 V8）。**只要 20MB 成功，即使 50/100MB 全失败，也只影响交付策略（大视频转网盘链接），不影响 bot_weixin.py 开发。**

## V5 · 连发限流

**目的**：确认高频消息不会触发服务端限制（源码已有 3 秒防抖 + 退避熔断，验证服务端是否还有额外限制）。

### 步骤

1. 在微信里 1 分钟内连发 10 条短消息（如「测试1」「测试2」……每条间隔 3-5 秒）
2. 观察 bot 的反应

### V5 通过判定

- [ ] bot 正常回复（预期多条被合并成 1-2 次回复，这是正常防抖，不是丢消息）
- [ ] 发送过程微信端无「消息发送失败/红色感叹号」
- [ ] 终端日志无连续 rate limit 报错（查日志命令见 V8；偶尔一条 rate limit 并自动恢复 = 可接受）

## V6 · 隔夜定时推送（关键项：雷达推送的通道基础）

**目的**：验证 bot 在你**长时间没发消息**的情况下，能否主动推送（tokenless 降级路径）。选题雷达每天早上推送清单就靠它。

### 步骤

**6.1 检查 WSL 时区**

```bash
date
```

预期：显示 CST（中国标准时间）。若是 UTC → 推送时间会有 8 小时偏差，把 `date` 输出发我，我给你校正命令。

**6.2 创建定时任务**

在微信里对 bot 说：

> 帮我创建一个定时任务：明天早上 8 点整，给我发一条消息，内容是「ClawBot 推送测试」

bot 会确认创建（它自己会调用 cron 工具）。如果它说不会/失败 → 截图发我。

**6.3 当晚不再给 bot 发任何消息**（这是本项验证的核心条件：隔夜静默）

**6.4 次日 8 点后看微信**

### V6 结果判定

- [ ] 次日 8 点左右收到「ClawBot 推送测试」→ **通过**：tokenless 推送成立，雷达推送方案成立
- [ ] 没收到 → **失败**：查日志（V8 命令）找 sendmessage 相关报错贴回来。结论不致命：bot_weixin.py 加「用户下次对话时补发」兜底即可，但推送体验降级

## V7 · 多用户配对

**目的**：验证第二个真人微信号能经 DM pairing 成为用户（设计 3.6 多用户白名单的最小验证）。

**准备**：第二个微信号（家人/朋友手机，或你的微信小号）。

### 步骤

**7.1 用第二个微信号联系 bot**

用第二个微信号给机器人发一条消息（如「你好」）。

> 入口说明：扫码登录后 bot 会以联系人形式出现在你的微信；第二个号如何触达它，可能的方式是微信内搜索该 bot 名称或由你分享名片。**这一步沙箱无法预判具体入口**——如果找不到入口，把你微信里看到的 bot 界面截图发我。

**7.2 触发配对**

第二个号发消息后，bot 应回复一条配对码/一键配对命令（ pairing 流程，源码已确认存在）。

**7.3 你在终端批准**

把配对命令粘贴到 Ubuntu 终端执行（或 `hermes pairing approve` + 提示的参数）。

**7.4 验证第二个号可用**

第二个微信号再发一条消息，bot 正常回复。

**7.5 验证白名单隔离**

- [ ] 第二个号与你的会话互不串扰（它问的问题不影响你的会话上下文）
- [ ] 再找一个未配对的第三个号发消息 → 收到的是配对提示而非正常回复（白名单生效）

### V7 通过判定

- [ ] 第二个号配对后可正常对话
- [ ] 未配对号被拦截

## V8 · 七天稳定性压测（从 V1 完成当天起算）

**目的**：确认网关可以常驻无人值守。这是「服务你电脑上的用户」的最终形态。

### 每日固定检查（建议固定时间，共 7 天）

| 检查 | 操作 | 记录 |
|---|---|---|
| 网关活着 | `hermes gateway status` | ☐ 正常 ☐ 异常（现象：__） |
| 消息延迟 | 微信发「ping」，看多久收到回复 | __ 秒 |
| 错误扫描 | 见下方日志命令 | 报错摘要 |

日志命令（服务名以 1.8 安装时终端输出的为准）：

```bash
journalctl --user -u hermes-gateway --since "24 hours ago" | grep -iE "expired|rate|error|fail" | tail -20
```

### 三个关键观察点

1. **Day 1 重启测试**：重启电脑 → 等 2 分钟 → `hermes gateway status` 应显示运行中（user service 自启）→ 微信发消息应正常回复
2. **-14 会话过静默**：若某次发消息后 bot **约 10 分钟无响应**且日志出现 `-14`/`expired` → 记录出现次数（源码行为：自动暂停 10 分钟后恢复，不崩溃；高频出现则 bot_weixin.py 需加主动重连）
3. **掉线是否要重扫**：日志出现断线时，是否需要重新扫码（不需要=可无人值守；需要=记录频率）

### V8 通过判定（Day 7 汇总）

- [ ] 7 天内无「必须人工干预才能恢复」的故障（自动恢复/一条命令恢复 = 可接受）
- [ ] -14 静默出现 __ 次
- [ ] 重启自启正常 ☐ / 异常（现象：__）

**扩展形态结论**（原「扩展点探查」项的答案）：

| 形态 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| A · hermes skill | 流水线做成 skill，消息 → hermes agent → skill | 部署最简单 | 每条消息过 hermes 的 LLM，时延/成本高 |
| B · hermes 通道 + 自建 Router | hermes gateway 跑 weixin adapter，hook/plugin 转发给我们的 Router | 协议升级有人维护 | hermes 全家桶，仍需 LLM key |
| **C · 移植 WeixinAdapter（推荐）** | bot_weixin.py 按 MIT 源码裁剪（仅依赖 aiohttp + cryptography），挂自己的 Router | 最贴合设计 3.3 TriggerAdapter；部署最轻 | iLink 协议演进自己跟（channel_version 2.2.0） |

推荐路径：本手册验证期用 hermes gateway 快速验通道；`bot_weixin.py` 开发走形态 C。验证结论（服务端阈值、稳定性）直接适用于 C。
